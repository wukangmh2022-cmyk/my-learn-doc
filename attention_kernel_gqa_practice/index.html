11.2 Attention Kernel 实战：QK、Softmax、PV 与 GQA¶

实战目标¶

本篇从一个 Attention Head 的标量公式开始，依次完成：

  1. 可验证的 CPU Reference；
  2. MHA 与 GQA 的 Head 映射；
  3. 三阶段 GPU 基线：QK、Softmax、PV；
  4. Online Softmax 与 QK/Softmax/PV 融合；
  5. KV 分块、异步搬运和 Shape 特化；
  6. 正确性、性能和边界条件验收。

最终实现聚焦 Decode：每条序列只有一个 Query Token，历史 K/V 来自 KV Cache。Prefill 应优先使用成熟的 FlashAttention 后端，不应把 Decode 特化 Kernel 直接套到大 Query Length 上。

一、先把计算流手推清楚¶

对一个 Query Head，设：

  • $q \in \mathbb{R}^{D}$；
  • $K,V \in \mathbb{R}^{T \times D}$；
  • $D$ 为 Head Size；
  • $T$ 为 Context Length。

第一步计算 Score：

$$ s_t = \frac{q \cdot k_t}{\sqrt{D}} $$

第二步执行稳定 Softmax：

$$ m = \max_t s_t $$

$$ p_t = \frac{e^{s_t-m}}{\sum_j e^{s_j-m}} $$

第三步加权求和：

$$ o_d = \sum_{t=0}^{T-1} p_t v_{t,d} $$

数据流为：

flowchart LR
    Q["Q: D"] --> DOT["QK Dot"]
    K["K: T x D"] --> DOT
    DOT --> SCORE["Scores: T"]
    SCORE --> MAX["Row Max"]
    MAX --> EXP["Exp + Row Sum"]
    EXP --> PROB["Probabilities: T"]
    PROB --> PV["PV Reduction"]
    V["V: T x D"] --> PV
    PV --> O["Output: D"]

朴素三 Kernel 实现会把 Scores[T] 和 Probabilities[T] 写回显存并再次读取。融合的核心目标是让这些中间状态停留在寄存器或片上存储中。

二、建立 CPU Reference¶

CPU Reference 必须表达数学语义，而不是复刻 GPU 的优化结构：

void attention_ref(
    const float* q,
    const float* k,
    const float* v,
    float* out,
    int context_len,
    int head_size)
{
    std::vector<float> scores(context_len);
    const float scale = 1.0f / std::sqrt(static_cast<float>(head_size));

    float row_max = -std::numeric_limits<float>::infinity();
    for (int t = 0; t < context_len; ++t) {
        float dot = 0.0f;
        for (int d = 0; d < head_size; ++d)
            dot += q[d] * k[t * head_size + d];
        scores[t] = dot * scale;
        row_max = std::max(row_max, scores[t]);
    }

    float denominator = 0.0f;
    for (float& score : scores) {
        score = std::exp(score - row_max);
        denominator += score;
    }

    std::fill(out, out + head_size, 0.0f);
    for (int t = 0; t < context_len; ++t) {
        const float probability = scores[t] / denominator;
        for (int d = 0; d < head_size; ++d)
            out[d] += probability * v[t * head_size + d];
    }
}

验收至少覆盖 FP32 Reference、FP16/BF16 GPU 输入、非 2 的幂 Context Length、T=1、最大 Context Length和随机极大 Logit。

三、GQA 的 Head 映射¶

MHA 中 Q、K、V Head 数相同。GQA 让多组 Query Head 共享一个 KV Head：

$$ group_size = \frac{H_q}{H_{kv}} $$

$$ kv_head(q_head) = \left\lfloor \frac{q_head}{group_size} \right\rfloor $$

例如 Hq=16, Hkv=2，每 8 个 Query Head 共享一个 KV Head：

Query Head KV Head
0 至 7 0
8 至 15 1

KV Cache 元素数量相对同 Head 数的 MHA 为：

$$ \frac{H_{kv}}{H_q}=\frac{2}{16}=\frac{1}{8} $$

这是 KV Head 维度上的理论缩减。实际总显存还包含 Block Padding、Allocator 元数据、对齐和其他模型状态，不能把整个推理显存概括为缩小到八分之一。

GQA 带来的 Kernel 机会¶

同组 Query Head 会读取同一个 K/V Head。若一个 Thread Block 同时处理多个同组 Query Head，可以复用已加载的 K/V Tile；若每个 Query Head 使用独立 Block，则共享只发生在 L2/L1 Cache 层，显式复用机会会丢失。

设计选择：

映射 优点 风险
一个 CTA 处理一个 Q Head 简单、并行 CTA 多 同组 KV 重复读取
一个 CTA 处理一组 Q Head 可显式复用 KV Tile 寄存器和 Shared Memory 压力上升
一个 CTA 处理部分 Q Head 在复用与 Occupancy 间折中 需要 Shape 特化

四、先实现三 Kernel GPU 基线¶

Kernel A：QK¶

Grid 可按 [batch, q_head, context_tile] 组织。每个 CTA 读取一个 Q Head，并流式处理若干 K Token：

// 伪 CUDA，仅表达映射。
__global__ void qk_kernel(
    const half* q, const half* k, float* scores,
    int context_len, int head_size)
{
    int token = blockIdx.x;
    int q_head = blockIdx.y;
    float partial = 0.0f;
    for (int d = threadIdx.x; d < head_size; d += blockDim.x)
        partial += __half2float(q[q_head * head_size + d])
                 * __half2float(k[(token * num_kv_heads + kv_head(q_head)) * head_size + d]);
    float dot = block_reduce_sum(partial);
    if (threadIdx.x == 0)
        scores[q_head * context_len + token] = dot * rsqrtf(float(head_size));
}

Kernel B：Row-wise Softmax¶

每个 CTA 处理一行 Score，先 Reduce Max，再 Reduce Sum。必须先减 Max，不能直接计算 exp(score)。

Kernel C：PV¶

每个 CTA 处理一个输出 Head，沿 Context 维归约 probability * V。输出维度 D 可映射到 Warp Lane 或多个 Warp。

三 Kernel 版本的意义是建立可测基线，并确认每个中间结果与 CPU Reference 对齐。不要跳过基线直接融合，否则错误无法定位到具体阶段。

五、融合策略一：把 Row Max 融入 QK¶

QK 计算每个 Score 时同步维护当前 Tile 的最大值，不再单独遍历 Score Buffer：

for each KV tile:
    scores_tile = Q dot K_tile
    tile_max = max(scores_tile)
    running_max = max(running_max, tile_max)

若仍将完整 Score 写回显存，这只消除一次 Max 遍历；若继续使用 Online Softmax，则 Score 甚至不必形成全局 Buffer。

六、融合策略二：Online Softmax 直接累加 PV¶

对每个 KV Tile 维护三个状态：运行最大值 $m$、归一化分母 $l$、未归一化输出 $o$。

新 Tile 到达时：

$$ m' = \max(m, \max(s_{tile})) $$

$$ \alpha = e^{m-m'} $$

$$ l' = \alpha l + \sum_i e^{s_i-m'} $$

$$ o' = \alpha o + \sum_i e^{s_i-m'}v_i $$

处理完全部 Tile 后：

$$ output = \frac{o}{l} $$

这样 Softmax 权重产生后立即消费 V，不写回 Probability Buffer。需要注意：当运行最大值更新时，旧分母与旧输出都必须乘同一个校正因子 $\alpha$。

for (int tile = 0; tile < num_tiles; ++tile) {
    load_kv_tile_async(tile);
    wait_for_kv_tile();

    compute_scores(q_fragment, k_tile, score_fragment);
    float new_max = max(running_max, reduce_max(score_fragment));
    float correction = expf(running_max - new_max);

    denominator *= correction;
    output_fragment *= correction;
    for (int i = 0; i < valid_tokens_in_tile; ++i) {
        float weight = expf(score_fragment[i] - new_max);
        denominator += weight;
        output_fragment += weight * v_tile[i];
    }
    running_max = new_max;
}
output_fragment /= denominator;

这里的 output_fragment 可能大到无法完全放在寄存器中。Head Size、同 CTA 处理的 Q Head 数和 Warp 数共同决定寄存器压力，因此融合不是越彻底越好。

七、计算与访存重叠¶

双缓冲把 KV Tile 的加载与前一个 Tile 的计算重叠：

stage 0: load tile 0
stage 1: compute tile 0 | load tile 1
stage 2: compute tile 1 | load tile 2
...

在 CUDA 上可使用 cp.async、TMA 或框架封装的异步 Copy；在其他加速器上可能对应 DMA/专用数据搬运指令。异步 API 只建立可能性，必须确认：

  • Copy 和 Compute 使用不同硬件路径；
  • Buffer 双份且没有覆盖仍在使用的数据；
  • Barrier/Commit/Wait 位置正确；
  • Tile 计算量足以覆盖加载延迟；
  • Nsight 时间线中确实出现重叠。

用户提供的“VSice”不是通用 CUDA 术语。若它是特定芯片或内部 SDK 的搬运单元，应在文档中补充硬件与 API 来源；通用表述使用异步 Copy/DMA。

八、Shape 特化¶

通用 Kernel 必须处理任意 head_size、Context Length、数据类型和对齐；特化 Kernel 可以把这些条件变成编译期常量：

template<int HEAD_SIZE, int KV_TILE, int WARPS>
__global__ void decode_attention_specialized(...);

可特化维度：

  • HEAD_SIZE = 64/80/96/128/256；
  • Context Length 上限或 Bucket；
  • Hq/Hkv Group Size；
  • FP16、BF16 或 FP8 KV Cache；
  • Block Size 与内存对齐；
  • 是否存在 Attention Mask、Sliding Window 或 ALiBi。

Dispatch 层负责选择最小覆盖 Shape 的 Kernel，未命中时回退通用实现。特化数量过多会增加编译时间、二进制大小和测试矩阵，应由真实流量中的 Shape 分布驱动。

十、完成标准¶

  • CPU Reference 与三 Kernel 基线逐阶段对齐；
  • MHA、MQA、GQA 的 Head 映射均有测试；
  • Online Softmax 在极大/极小 Logit 下数值稳定；
  • 非整 Tile 的 Context Length 不越界；
  • 融合版不产生 Score/Probability 全局 Buffer；
  • Nsight 证明优化减少了显存事务或 Kernel 间隙；
  • 每个性能数字都绑定硬件、Shape、版本和测量范围。

这篇实战连接第 6.4 节 FlashAttention、第 7 章 Attention 推导、第 4.2 节 Tiling 和第 4.3 节异步流水线。核心并不是记住一个融合模板，而是从中间结果的生命周期推导：能在片上立即消费的数据，就不应先写回 HBM 再读取。
