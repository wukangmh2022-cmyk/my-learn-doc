7. LLM 核心算子：从推导到 CUDA 实现¶

概述¶

前面第 6 章你写过 Reduce / Scan / Radix Sort / FlashAttention，已经证明了"图形算法 → AI 算子"的同构。但 LLM 推理有自己一套高频且面试必考的算子，它们要么缺数学推导、要么缺手写代码能力：

  • Attention 家族：KQV 标准 Attention、MHA / MQA / GQA 变种——几乎每个 LLM 推理面试题的底层。
  • 归一化与位置：Softmax / Online Softmax、RMSNorm、RoPE——Transformer 每一层都在跑。
  • 矩阵运算：GEMM（Prefill 主导）、GEMV（Decode 主导）、Transpose（Kernel 间搬运，且与你刚学的 Bank Conflict 强相关）。

本章程式：每个算子都按"数学推导 → 图形映射 → CUDA 实现 → 面试要点"四段走。推导是让你"真懂"，代码是让你"能写"，映射是让你"记得住"。

7.1 标准 KQV Attention 数学推导¶

数学¶

给定 Query / Key / Value（序列长度 n，头维度 d_k）：

\[ \text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^T}{\sqrt{d_k}}\right) V \]

展开成一步：

  1. 打分：\(S = QK^T \in \mathbb{R}^{n\times n}\)，其中 \(S_{ij} = q_i \cdot k_j\)（query \(i\) 与 key \(j\) 的相似度）。
  2. 缩放：除以 \(\sqrt{d_k}\) 防止点积过大导致 softmax 梯度消失。
  3. 归一化：\(P = \text{softmax}(S)\)（每行和为 1，行内是"对序列所有位置的注意力权重"）。
  4. 加权求和：\(O = P V\)，每个输出位置是 Value 的加权和。
flowchart LR
    X["输入 X"] --> Q["Q = XWq"]
    X --> K["K = XWk"]
    X --> V["V = XWv"]
    Q --> S["Scores = QK^T / sqrt(dk)"]
    K --> S
    S --> P["按行 Softmax"]
    P --> O["O = PV"]
    V --> O

Multi-Head Attention（MHA）：把 d_model 拆成 h 个头，每头维度 \(d_k = d_{model}/h\)，各头独立算 Attention 再拼接，最后过输出投影 \(W_O\)：

\[ \text{MHA}(X) = \text{Concat}(head_1,\dots,head_h) W_O,\quad head_i = \text{Attention}(XW_{Q_i}, XW_{K_i}, XW_{V_i}) \]

计算复杂度 \(O(n^2 d)\)，显存 \(O(n^2)\)（要存 \(P\) 这个 \(n\times n\) 注意力矩阵）——这正是 FlashAttention（6.4）要干掉的中间量。

图形 → AI 映射¶

Attention 步骤 图形对应
\(QK^T\)（每 query 与所有 key 打分） 延迟着色 / 多光源着色：每像素对所有光源做点积算光照贡献
\(\text{softmax}\)（归一化权重） 对一组光源贡献做归一化混合权重（类似加权混合多张 lightmap）
\(PV\)（加权求和） 按权重把多个光源颜色累加到最终像素

一句话：Attention 就是"每个 fragment 向序列里所有其它位置（光源）请求贡献并加权求和"。你写过的延迟着色就是这个结构，只是光源数 = 序列长度 \(n\)。

CUDA 实现（正确性参考版）¶

// 一个 Block 处理一个 Query。动态 Shared Memory 至少为 n * sizeof(float)。
// 省略 mask、batch、head 和低精度路径，仅用于解释数据流。
__global__ void naive_attention(
    const float* Q, const float* K, const float* V,
    float* O, int n, int d) {
    int q = blockIdx.x;
    int tid = threadIdx.x;
    extern __shared__ float scores[];

    for (int j = tid; j < n; j += blockDim.x) {
        float s = 0.0f;
        for (int k = 0; k < d; ++k)
            s += Q[q*d + k] * K[j*d + k];
        scores[j] = s * rsqrtf((float)d);
    }
    __syncthreads();

    if (tid == 0) {
        float m = -CUDART_INF_F;
        for (int j = 0; j < n; ++j) m = fmaxf(m, scores[j]);
        float sum = 0.0f;
        for (int j = 0; j < n; ++j) {
            scores[j] = expf(scores[j] - m);
            sum += scores[j];
        }
        for (int j = 0; j < n; ++j) scores[j] /= sum;
    }
    __syncthreads();

    for (int k = tid; k < d; k += blockDim.x) {
        float acc = 0.0f;
        for (int j = 0; j < n; ++j) acc += scores[j] * V[j*d + k];
        O[q*d + k] = acc;
    }
}

面试要点：标准三 Kernel 实现若物化整张 \(S/P\)，会产生 \(O(n^2)\) 中间存储。上面的参考 Kernel 只保留一行分数，但 Shared Memory 限制了序列长度，且 Softmax 由单线程执行。生产实现需要分块归约、Mask、向量化读写和 FlashAttention 式在线更新。

7.2 变种：MHA / MQA / GQA¶

Attention 的计算量主要卡在访存 KV Cache（Decode 阶段每生成一个 token 都要把所有历史 K/V 从显存读进来）。三种变体本质是在"质量"和"KV 显存/带宽"之间取舍：

变体 K/V 头数 KV Cache 大小（相对 MHA） 质量 代表模型
MHA = \(h\)（每头独立） 1× 表达能力基线 原始 Transformer、GPT-3
MQA 1（所有 Query 头共享 K/V） \(1/h\) 取决于模型与训练 PaLM、Falcon 的部分版本
GQA \(g\)（每组 Query 头共享 K/V） \(g/h\) 常作为质量/带宽折中 LLaMA 2 70B、LLaMA 3、Mistral

KV Cache 显存公式（每 token、每层）：

\[ \text{MHA：} 2 \times h \times d_h \times 2\ \text{字节（fp16）} $$ $$ \text{GQA：} 2 \times g \times d_h \times 2\ \text{字节} \]

例：若 \(h=32, d_h=128, g=8\)，仅按 K/V 元素数计算，GQA Cache 是同形状 MHA 的 \(8/32 = 1/4\)。端到端带宽和延迟还包含投影、调度与其他算子，不能直接推导为整步快 4 倍。

图形 → AI 映射¶

变体 图形直觉
MHA 每个像素独立一张 Shadow Map（最准但最占显存）
MQA 所有像素共享一张 Shadow Map（省显存，但远处精度差）
GQA 把屏幕分成几块（tile），每块共享一张 Shadow Map（精度/显存折中）

GQA 与 Tiled Rendering 都利用“在一组消费者之间共享资源”的直觉，但分组维度不同：GQA 沿 Attention Head 分组，Tiled Rendering 通常沿屏幕空间分块。它们不是同一种算法。

面试要点¶

  • 能画出三者 K/V 头的形状差异（头维度上"广播"）。
  • 能说清 MQA/GQA 省的是 KV 的"访存带宽"不是"算力"——Decode 是 memory-bound，所以收益巨大。
  • GQA 的 num_kv_heads 参数就是 \(g\)；vLLM 里 tensor_parallel_size 还会再切 \(g\)。

7.3 Softmax 与 Online Softmax¶

标准 Softmax（数值稳定版）¶

\[ \text{softmax}(x_i) = \frac{e^{x_i - m}}{\sum_j e^{x_j - m}},\quad m = \max_j x_j \]

减 max 是为了防止 exp 溢出——你永远先做 m = max，再减它。

Online Softmax（FlashAttention 的核心技巧）¶

标准做法要先把整行 \(S\) 算完才能做 softmax（因为要全局 max 和 sum）。但 FlashAttention 把行切成 tile，一边读 tile 一边在线更新 max 和 sum，从不物化整行：

维护运行最大值 \(m\) 和运行分母 \(\ell\)，来一个新 tile（局部 scores \(x\)，局部 max \(m_{local}\)，局部 sum \(\ell_{local}\)）：

\[ m_{new} = \max(m_{old},\, m_{local}) $$ $$ \ell_{new} = e^{m_{old}-m_{new}} \cdot \ell_{old} + e^{m_{local}-m_{new}} \cdot \ell_{local} \]

输出累加器同步校正：

\[ O_{new} = e^{m_{old}-m_{new}} \cdot O_{old} + e^{m_{local}-m_{new}} \cdot (\text{该 tile 的 } P_{local} \cdot V) \]

最终 \(O = O_{final} / \ell_{final}\)。

图形 → AI 映射¶

概念 图形对应
Online softmax 增量更新 时间性累积（Temporal Accumulation）：每帧来一帧新样本，用校正因子把旧平均"拉"到新平均，而不重算全部历史
减 max 防溢出 HDR 色调映射里先做 log / 找最大亮度再归一化，防止高光爆掉

面试要点¶

  • 必须能口述 online softmax 的两条更新公式（max 取大、sum 带校正因子）。
  • 说清为什么需要它：让 FlashAttention 不把 \(n\times n\) 的 \(P\) 写回 HBM，从而降显存、提带宽利用率。

7.4 RMSNorm / LayerNorm¶

LayerNorm¶

对特征维（最后一维，长度 d）归一化：

\[ \mu = \frac{1}{d}\sum_i x_i,\quad \sigma^2 = \frac{1}{d}\sum_i (x_i-\mu)^2,\quad \hat x_i = \frac{x_i-\mu}{\sqrt{\sigma^2+\varepsilon}}\cdot \gamma_i + \beta_i \]

RMSNorm（LLaMA 等模型常用）¶

去掉均值中心化、去掉 \(\beta\)，只用均方根：

\[ \text{RMS}(x) = \sqrt{\frac{1}{d}\sum_i x_i^2 + \varepsilon},\quad \hat x_i = \frac{x_i}{\text{RMS}(x)} \cdot \gamma_i \]

它省去均值中心化和偏置项，计算与数据流更简单。模型质量取决于架构与训练过程，不能概括为对所有模型都“几乎无损”。

图形 → AI 映射¶

算子 图形对应
LayerNorm 对一块 texel 做亮度归一化再乘增益（类似 tone-mapping 前的 normalize）
RMSNorm 只算 RMS 不减去均值 = 类似于只对"对比度/幅度"做归一化，不关心整体偏移（像去直流分量的滤波）

CUDA 实现要点¶

// 伪代码：block_reduce_sum 必须返回整个 Block 的平方和。
__global__ void rmsnorm(const float* x, const float* gamma, float* y, int d) {
    int row = blockIdx.x;
    float ss = 0.0f;
    for (int i = threadIdx.x; i < d; i += blockDim.x)
        ss += x[row*d + i] * x[row*d + i];
    float total_ss = block_reduce_sum(ss);  // 见 5.5；结果广播到所有线程
    float inv_rms = rsqrtf(total_ss / d + 1e-6f);
    for (int i = threadIdx.x; i < d; i += blockDim.x)
        y[row*d + i] = x[row*d + i] * inv_rms * gamma[i];
}

面试要点¶

  • 能说清 RMSNorm 比 LayerNorm 少做"减均值"和"加 β"，所以更快。
  • 归约用 warp shuffle（5.5）比用 shared memory 更省 bank 冲突——接回你刚学的第 5.2 章。

7.5 RoPE（旋转位置编码）¶

位置编码让模型感知 token 顺序。RoPE（Rotary Position Embedding）把"位置"编码成旋转，使 \(q\cdot k\) 只依赖相对位置 \(m-n\)。

推导¶

对相邻两维 \((x_{2i}, x_{2i+1})\) 定义频率 \(\omega_i = 10000^{-2i/d}\)。位置 \(m\) 使用角度 \(\theta_{m,i}=m\omega_i\)：

\[ \begin{pmatrix} q'_{2i} \\ q'_{2i+1} \end{pmatrix} = \begin{pmatrix} \cos\theta_{m,i} & -\sin\theta_{m,i} \\ \sin\theta_{m,i} & \cos\theta_{m,i} \end{pmatrix} \begin{pmatrix} q_{2i} \\ q_{2i+1} \end{pmatrix} \]

写成旋转矩阵 \(R(\theta_i)\)，则位置 \(m\) 的 query 为 \(R(m\theta_i)q\)，位置 \(n\) 的 key 为 \(R(n\theta_i)k\)。关键性质：

\[ (R(m\theta_i)q)^T (R(n\theta_i)k) = q^T R((n-m)\theta_i)\,k \]

——内积只与相对位置 \((n-m)\) 有关，位置信息被"旋"进了向量本身。

复数视角：把每对维当成复数 \(z = x_{2i} + i\,x_{2i+1}\)，乘上 \(e^{i m\theta_i}\) 即旋转。

CUDA 实现¶

// RoPE：Q 和 K 都要按模型规定的维度布局应用旋转。
__global__ void rope(float* q, const float* cos_cache, const float* sin_cache,
                     int pos, int d) {
    int i = threadIdx.x;                // 第 i 对
    if (2*i+1 >= d) return;
    float c = cos_cache[pos * (d/2) + i];
    float s = sin_cache[pos * (d/2) + i];
    float a = q[2*i], b = q[2*i+1];
    q[2*i]   = a*c - b*s;
    q[2*i+1] = a*s + b*c;
}

图形 → AI 映射¶

概念 图形对应
旋转一对维度 法线变换：用旋转矩阵 \(R\) 把 TBN 中的法线旋到世界空间
相对位置依赖 像屏幕空间导数（\(dFdx/dFdy\)）只关心相邻像素相对偏移，不关心绝对坐标

面试要点¶

  • 能写出旋转矩阵形式，并说明为什么相对位置被编码进内积。
  • 能说 10000 基的来历（不同频率覆盖不同尺度），以及长上下文常做 NTK-aware / 线性缩放 外推。

7.6 GEMM（矩阵乘：Prefill 主导）¶

数学¶

\(C_{m\times n} = A_{m\times k} \times B_{k\times n}\)。LLM Prefill 阶段（一次处理整段 prompt）绝大多数是 GEMM。

分块 + Shared Memory Tiling（接 5.2 Bank Conflict）¶

标准做法：把 \(C\) 切成 TILE×TILE 小块，每个 Block 把对应 \(A\)、\(B\) 的 Tile 搬进 Shared Memory 累加。Padding 或 Swizzle 是否必要取决于 Warp 的实际访问方向；下面这个朴素行主序访问不因 [32][32] 必然产生 Bank Conflict。

template<int TILE>
__global__ void gemm_tiled(const float* A, const float* B, float* C,
                           int m, int n, int k) {
    __shared__ float sA[TILE][TILE];
    __shared__ float sB[TILE][TILE];
    int row = blockIdx.y*TILE + threadIdx.y;
    int col = blockIdx.x*TILE + threadIdx.x;
    float sum = 0.0f;
    for (int t = 0; t < k; t += TILE) {
        sA[threadIdx.y][threadIdx.x] =
            (row < m && t + threadIdx.x < k) ? A[row*k + t + threadIdx.x] : 0.0f;
        sB[threadIdx.y][threadIdx.x] =
            (t + threadIdx.y < k && col < n) ? B[(t+threadIdx.y)*n + col] : 0.0f;
        __syncthreads();
        #pragma unroll
        for (int i = 0; i < TILE; ++i) sum += sA[threadIdx.y][i]*sB[i][threadIdx.x];
        __syncthreads();
    }
    if (row < m && col < n) C[row*n + col] = sum;
}

生产级实现用 Tensor Core（见 9.1 / 原 7.1），以 wmma::mma_sync 一次算 16×16×16 的小块，吞吐是 CUDA Core 的数倍。

图形 → AI 映射¶

概念 图形对应
Tiling GEMM Tiled Deferred Shading / TBDR：把大计算切成 tile 放进片上内存算
Tensor Core 加速 专用 ALU，类比固定功能纹理单元替你做原本要 Shader 手算的事

7.7 GEMV（矩阵-向量：Decode 主导）¶

数学与特性¶

\(y_{m} = W_{m\times k} \cdot x_k\)。自回归 Decode 每个序列每步只新增一个 token；当并发批量较小时，线性层接近 GEMV，批量增大后会成为窄 GEMM。

关键：GEMV 是 memory-bound——要把整个权重矩阵 \(W\) 从 HBM 读进来，而每读一个元素只做一次乘加。算术强度极低，瓶颈在带宽不在算力。

优化方向¶

  • 把 \(x\) 搬进 Shared Memory 复用（避免每读一行权重都重读 \(x\)）。
  • 相对 FP16，INT8/FP8 的元素宽度通常减半；相对 FP32 则为四分之一。缩放因子、元数据和反量化也有开销。
  • 多 token 时把 GEMV 聚成小 GEMM（batch GEMM）提升算术强度。

图形 → AI 映射¶

概念 图形对应
GEMV 读整张权重算一个向量 像对一个像素采样整张纹理图集——读得多、算得少，瓶颈在"取数带宽"

7.8 Transpose / 数据重排（与 Bank Conflict 强相关）¶

数学¶

\(Out[j][i] = In[i][j]\)。Kernel 间常需要转置（如 NHWC↔NCHW、或 attention 中 K 的布局调整）。

朴素实现的坑¶

// 输入读取合并，但输出对相邻线程是跨步写；这里没有写入数据竞争。
out[col*N + row] = in[row*N + col];

分块转置 + Padding（经典 Bank Conflict 案例）¶

__global__ void transpose(const float* in, float* out, int N) {
    __shared__ float tile[32][32+1];    // +1 padding 破解 bank conflict
    int x = blockIdx.x*32 + threadIdx.x;
    int y = blockIdx.y*32 + threadIdx.y;
    tile[threadIdx.y][threadIdx.x] = in[y*N + x];
    __syncthreads();
    int x2 = blockIdx.y*32 + threadIdx.x;
    int y2 = blockIdx.x*32 + threadIdx.y;
    out[y2*N + x2] = tile[threadIdx.x][threadIdx.y];  // 全局写入保持合并
}

这正是第 5.2 章 Bank 理论的最佳练兵：把 tile[ty][tx] 写进去、tile[tx][ty] 读出来，若不加 +1 padding，32 线程会全部撞同一个 bank。

图形 → AI 映射¶

概念 图形对应
Transpose + swizzle 纹理 swizzle / 像素格式重排（如 RGBA→BGRA、tile-based 纹理布局），目的同样是让内存访问模式适配硬件缓存行

下一步：把这些零件焊成一台机器¶

本章拆的是单个算子：Attention 的公式、RMSNorm 的一次规约、RoPE 的旋转矩阵、GEMM/GEMV 的访存模式。但零件摆一桌不等于会造机器 —— 你还需要知道它们按什么顺序串起来、KV Cache 挂在哪一步、FFN（本章没展开，它其实占了一个 Block 三分之二的参数）长什么样、最后 logits 怎么变成 token。
