7.1 Tensor Core vs CUDA Core：专用矩阵乘单元与通用 ALU 的分工

概述

现代 GPU 的 SM（流式多处理器）内部并非只有一种计算单元，而是包含两种分工截然不同的核心：CUDA Core 和 Tensor Core。理解它们的区别和协作方式，是理解 AI 推理性能的关键。

用你的渲染思维来翻译：就像图形管线里既有通用的 Pixel Shader ALU，又有专用的纹理采样器（TMU），两者在同一 Shader 程序中交替执行，各司其职。

CUDA Core：通用标量 ALU

本质

CUDA Core 本质上是一个完整的整数/浮点算术逻辑单元（ALU），支持所有常规指令：

  • 加减乘除（ADD, SUB, MUL, DIV）
  • 比较与选择（CMP, SEL）
  • 类型转换（F2I, I2F）
  • 分支跳转（BRA, CALL, RET）
  • 逻辑运算（AND, OR, XOR）

每一个 CUDA Core 在每一个时钟周期处理一个标量操作——即一次只处理一个数值。

灵活性

CUDA Core 是"万能工"，可以执行任何你能想到的计算逻辑：

// ReLU：一次比较 + 一次选择 → CUDA Core 执行
float relu(float x) {
    return x > 0 ? x : 0;
}

// Sigmoid：指数 + 除法 → CUDA Core 执行
float sigmoid(float x) {
    return 1.0f / (1.0f + expf(-x));
}

// GELU：乘加 + tanh + 乘加 → CUDA Core 执行
float gelu(float x) {
    const float sqrt_2_over_pi = 0.7978845608028654f;
    return 0.5f * x * (1.0f + tanhf(sqrt_2_over_pi * (x + 0.044715f * x * x * x)));
}

这些指令在 Tensor Core 的硬件逻辑里根本不存在。

Tensor Core：专用矩阵乘加单元

本质

Tensor Core 是一条"死脑筋"的专用流水线——它只认识一个操作：矩阵乘加（D = A × B + C）。

但它的可怕之处在于吞吐量：

属性 CUDA Core Tensor Core
单次操作粒度 1 个标量（1×1×1） 一个矩阵块（如 16×16×16）
单次乘加次数 1 次 FMA 4096 次 FMA（16×16×16）
数据访问模式 逐元素随机访问 规则块状加载
硬件代价 面积小，灵活 面积大，吞吐极高
指令集 完整（数百条指令） 唯一（mma.sync 系列）

工作方式：warp-level 矩阵乘

Tensor Core 的操作粒度是 warp 级 的，不是 thread 级的。一个 warp（32 个线程）协同工作，一次性完成一个矩阵块的乘加。

标准流程如下（使用 CUDA wmma 命名空间）：

#include <cuda_fp16.h>
#include <mma.h>

using namespace nvcuda;

// 定义矩阵维度：16×16×16 (m16n16k16)
wmma::fragment<wmma::matrix_a, 16, 16, 16, half, wmma::row_major> a_frag;
wmma::fragment<wmma::matrix_b, 16, 16, 16, half, wmma::col_major> b_frag;
wmma::fragment<wmma::accumulator, 16, 16, 16, float> c_frag;
wmma::fragment<wmma::accumulator, 16, 16, 16, float> d_frag;

// 1. 加载数据到寄存器（从 Shared Memory 加载）
wmma::load_matrix_sync(a_frag, shared_A, 16);  // A: [16, 128]
wmma::load_matrix_sync(b_frag, shared_B, 128); // B: [128, 16]
wmma::fill_fragment(c_frag, 0.0f);             // C 初始化为 0

// 2. 矩阵乘加：D = A × B + C
// 一条指令，完成 16×128 × 128×16 → 16×16，即 4096 次乘加
wmma::mma_sync(d_frag, a_frag, b_frag, c_frag);

// 3. 存储结果
wmma::store_matrix_sync(shared_C, d_frag, 16, wmma::mem_row_major);

关键：不需要循环累加 128 次——Tensor Core 在一个时钟周期内就把 4096 次乘加全部算完。

为什么 Tensor Core 如此之快

Tensor Core 的快，不是因为频率高，而是因为并行度高：

  • 同一个 warp 内的 32 个线程协同工作
  • 每个线程负责计算输出矩阵块的一部分
  • 硬件电路将乘加操作固化为一条流水线，消除了指令调度的开销
  • 结果是：Memory bandwidth becomes the bottleneck——Tensor Core 算得实在太快，数据搬运速度跟不上它的消耗速度

这就是为什么 Tiling 和 Shared Memory 管理在 AI Kernel 中如此关键：你需要确保数据搬运的速度能喂饱 Tensor Core。

图形渲染中的等价类比

没有 Tensor Core 时 → 没有纹理采样器时

场景 手动实现 硬件加速
图像模糊 像素循环读 9 个邻居，算 9 次乘加 硬件一次完成整个块的计算
双线性插值 手动用 float4 算插值 用 tex2D 硬件一步完成
矩阵乘 逐元素循环 128 次累加 Tensor Core 一次性算完 16×16×16

图形里最接近 Tensor Core 的等价物是 TMU（纹理采样单元） 中的 固定功能纹理采样器：

Pixel Shader 中的 tex2D()  →  硬件纹理采样器（TMU）一次性完成采样 + 插值
CUDA Kernel 中的 mma_sync →  Tensor Core 一次性完成矩阵乘加

两者都是： - 把频繁使用的计算模式固化为专用硬件电路 - 用户通过特定的指令/API调用，而不是手动实现算法 - 在同一个程序中和通用 ALU 交替执行，由硬件调度器自动路由

现代 GPU 中的混合执行流程

输入 → [矩阵乘 (Tensor Core)] → [激活函数 (CUDA Core)] → [矩阵乘 (Tensor Core)] → ...

图形等价：
纹理采样 (TMU) → [ALU 运算 (CUDA Core)] → 纹理采样 (TMU) → [ALU 运算 (CUDA Core)]

Tensor Core 和 CUDA Core 在 SM 内部无缝交替执行，由硬件调度器在指令级自动切换：

  1. 编译器生成指令：矩阵乘指令 → Tensor Core；标量运算指令 → CUDA Core
  2. Warp Scheduler 看到 mma.sync，将 warp 调度到 Tensor Core
  3. 看到普通 ALU 指令，调度到 CUDA Core
  4. 切换在纳秒级完成，无感知

维度 CUDA Core Tensor Core 图形等价物
本质 通用标量 ALU 专用矩阵乘加单元 Pixel Shader ALU vs TMU

关键结论

  1. Tensor Core 是专用电路，不是加速版的 CUDA Core——它只做矩阵乘加，做不了 ReLU
  2. CUDA Core 是通用 ALU——它什么都能做，但单次吞吐远低于 Tensor Core
  3. 两者在 SM 内部交替执行，由硬件调度器在指令级自动路由，程序员无感知
  4. 图形中最接近 Tensor Core 的等价物是 TMU 纹理采样器——都是固定功能硬件单元
  5. Tensor Core 算得实在太快，以至于显存带宽成为瓶颈——这就是 Tiling 和 Shared Memory 优化如此重要的根本原因

就像你的 GPU 在跑 Pixel Shader 时，纹理采样（TMU）和 ALU 计算（CUDA Core）自动交替一样——AI 推理中，Tensor Core 和 CUDA Core 也在同一 Kernel 内部无缝协作，各司其职。
