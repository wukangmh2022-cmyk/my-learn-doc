3.2 算子分类法 — Elementwise, Reduce, Scan, Gather/Scatter, Stencil, MatMul, Conv, Custom Fusion¶

概述¶

CUDA 算子虽然千变万化，但核心模式只有不到十种。这和图形渲染管线中的着色器阶段、Pass 类型是完全一一对应的。

核心洞察： "别管你是啥算法，在 GPU 眼里，只有三种访存模式——Map（逐元素）、Reduce（归约）、Stencil（模板）。" 所有算子本质上都是围绕这三种模式，对"如何把数据搬到 Shared Memory 里"做的不同包装。

算子分类总表¶

类别 CUDA 代表操作 对应的 Shader/Pass 类比 本质行为
1. Elementwise Add, Mul, ReLU, Sigmoid, SiLU Pixel Shader（像素着色器） 每个输出独立计算，不依赖邻居，瓶颈 = 访存带宽
2. Reduce Sum, Max, Mean, Softmax 分母 Render Target 混合 / Mipmap 生成 多个输入合并成一个输出，需要线程同步
3. Scan CumSum, CumProd, Prefix Sum Shadow Map 方向梯度 / Summed Area Table 每个输出依赖前面所有输入，有数据依赖链
4. Gather/Scatter IndexSelect, Embedding, torch.gather 纹理采样 / Vertex Fetch 根据索引读（Gather）或写（Scatter）数据
5. Stencil Conv2d, MaxPool, Depthwise Conv 纹理后处理 Filter（模糊/边缘检测） 滑窗计算，每个输出依赖输入的局部邻域
6. MatMul GEMM, BMM, Attention Q×K^T 顶点变换 (WVP) / Tiled Shading 二维矩阵乘法，利用 Tensor Core 做分块
7. 控制流 if, switch, 变长 Sequence 着色器中的 Discard/分支 SIMD 架构下的分支性能杀手
8. Custom Fusion 融合多个操作为一个 Kernel 多 Pass 合并成一个 Pass 减少中间显存读写，降低带宽消耗

逐类详解¶

1. Elementwise（逐元素）¶

定义： 对张量中的每个元素应用相同的操作，元素之间完全独立。

# 伪代码：Elementwise 的本质
output[i] = f(input[i])   # 或二元：output[i] = f(a[i], b[i])

CUDA 示例： ReLU 激活函数

__global__ void relu_kernel(float* input, float* output, int N) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < N) {
        output[idx] = fmaxf(0.0f, input[idx]);
    }
}
特性 说明
访存模式 Map——每个线程读一个元素，写一个元素
瓶颈 显存带宽（Memory-bound）
优化重点 合并访问（Coalesced Access）+ 向量化（float4 一次加载 4 个值）
图形类比 这就是 Pixel Shader——每个像素只依赖自己的 UV 坐标，不采样邻居

2. Reduce（归约）¶

定义： 将多个输入元素合并成一个（或少量）输出。

# 伪代码：Reduce 的本质
output = sum(input[0], input[1], ..., input[N-1])

CUDA 示例： 树形归约求和

__global__ void reduce_sum_kernel(float* input, float* output, int N) {
    extern __shared__ float shared[];
    int tid = threadIdx.x;
    int idx = blockIdx.x * blockDim.x + threadIdx.x;

    // 加载数据到 Shared Memory
    shared[tid] = (idx < N) ? input[idx] : 0.0f;
    __syncthreads();

    // 树形归约（每次减半）
    for (int s = blockDim.x / 2; s > 0; s >>= 1) {
        if (tid < s) {
            shared[tid] += shared[tid + s];
        }
        __syncthreads();
    }

    // 将每个 Block 的结果写回
    if (tid == 0) output[blockIdx.x] = shared[0];
}
特性 说明
访存模式 Reduce——多个输入 → 一个输出，需要跨线程通信
瓶颈 显存带宽 + 同步开销
优化重点 Shared Memory 分块归约 + Warp-level 归约（__shfl_xor_sync）
图形类比 Hi-Z 生成 / Mipmap也包含局部归约，但过滤规则、树的分组和输出语义不同

树形归约 = 倒立的树：叶子是 N 个输入，每层合并一半，最终到根节点只剩 1 个输出。和你写 Hi-Z（层次 Z）时的多 Pass 下采样一模一样。

3. Scan / Prefix Sum（扫描 / 前缀和）¶

定义： 每个输出元素依赖所有之前（或之前一部分）的输入元素。

# 伪代码：Exclusive Scan
output[i] = sum(input[0], input[1], ..., input[i-1])
特性 说明
访存模式 Reduce + 数据依赖链
瓶颈 跨线程通信 + 数据依赖强同步
优化重点 双缓冲（Blelloch 算法）+ Warp-level Shuffle + 循环展开
图形类比 Summed Area Table (SAT)——每个像素的值是它左上方所有像素的和

复杂度原因： 既有跨线程通信（类似 Reduce），又有数据依赖链（下一个元素必须等前一个算完）。

4. Gather / Scatter（聚集 / 散射）¶

定义： 根据索引列表读（Gather）或写（Scatter）数据。

Gather:   output[i] = input[index[i]]     // 读索引位置
Scatter:  output[index[i]] = input[i]     // 写索引位置

CUDA 示例： Embedding 查表

__global__ void embedding_gather_kernel(float* weight, int* indices,
                                         float* output, int vocab_size, int dim) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    int token_idx = idx / dim;
    int dim_idx = idx % dim;
    int word_id = indices[token_idx];

    output[idx] = weight[word_id * dim + dim_idx];
}
特性 说明
访存模式 Gather——读索引处的数据，访问模式不规则
瓶颈 Cache Miss——因为索引随机，硬件无法预取
优化重点 数据重排（按访问模式排序）+ Shared Memory 显式缓存
图形类比 纹理采样 (tex2D)——用 UV 坐标去纹理中取颜色；Vertex Fetch——按索引取顶点数据

GPU 视角： Gather 是 GPU 上最难优化的操作之一。纹理采样能利用硬件 TMU 和纹理 Cache，但 Tensor 的 Gather 只能靠程序员手动管理缓存。

5. Stencil / Conv（模板 / 卷积）¶

定义： 每个输出依赖于输入的一个固定局部邻域。

# 伪代码：3x3 卷积
output[y][x] = sum_{i=-1}^{1} sum_{j=-1}^{1} input[y+i][x+j] * kernel[i][j]
特性 说明
访存模式 Stencil——固定的邻域访问模式
瓶颈 显存带宽 + 边界处理 + 循环嵌套
优化重点 分块加载（Tiling）+ 双缓冲 + Tensor Core 加速
图形类比 高斯模糊 / 边缘检测 Filter——每个像素采样周围邻居加权平均

分块加载的要点： 加载 Tile 时必须多加载一圈 Halo 边界数据（比如 3x3 卷积的 Tile 需要额外加 1 圈 padding），这对 Shared Memory 的容量和加载策略提出了要求。

6. MatMul / GEMM（矩阵乘）¶

定义： C = A × B，两个二维矩阵相乘。这是 AI 推理中计算量最大、权重密度最高的操作。

// 伪代码：Tiled MatMul 的分块加载模式
__shared__ float tile_A[TILE_SIZE][TILE_SIZE];
__shared__ float tile_B[TILE_SIZE][TILE_SIZE];

tile_A[ty][tx] = A[row * stride + col];
tile_B[ty][tx] = B[row * stride + col];
__syncthreads();

for (int k = 0; k < TILE_SIZE; k++) {
    acc += tile_A[ty][k] * tile_B[k][tx];
}
特性 说明
访存模式 Map × Reduce 组合——每个输出是 A 的一行和 B 的一列的点积
瓶颈 计算量巨大 + 数据复用复杂
优化重点 分块策略（Tile Size）+ 双缓冲 + 寄存器缓存 + Tensor Core 指令 + 布局重排
图形类比 顶点变换 (World × View × Proj)——Mesh 的顶点乘以 MVP 矩阵；Tiled Shading——分块处理光照数据

GPU 视角： GEMM 是所有算子中最复杂的（六星难度），但它也是你最值得攻克的制高点——因为你已有的分块（Tiling）、双缓冲、Shared Memory 经验可以直接复用，只是多了 Tensor Core 的指令调用。

7. 控制流（Control Flow）¶

定义： Kernel 内部的分支逻辑。

if (condition) {
    // 某些线程执行这个分支
} else {
    // 其他线程执行另一个分支
}

GPU 视角： 在 SIMT（单指令多线程）架构下，分支是性能杀手。Warp 内的线程如果有分歧，硬件会串行化执行所有分支路径，然后屏蔽掉不满足条件的线程。这和你在 Shader 里尽量避免 if 是一个道理。

8. Custom Fusion（自定义融合）¶

定义： 将多个算子合并到一个 Kernel 中执行，消除中间内存读写。

// 不融合：3 次 Global Memory 读写
Elementwise(input) → Global Memory → Reduce(...) → Global Memory → Elementwise(...)

// 融合后：1 次 Global Memory 读写
FusedKernel(input) → 全部在 Shared Memory 内完成 → Global Memory
特性 说明
访存模式 混合模式（Map + Reduce 等）
瓶颈 从显存带宽消耗 → 计算/Shared Memory 容量上限
图形类比 多 Pass 合并——把光照+阴影+纹理采样合成一个复杂的 Pixel Shader，减少 RT 切换

可迁移的原则：减少中间结果和提交边界通常有利；但算子融合还要评估寄存器压力、Shared Memory、重计算与可调度性。

CUDA 核心设计哲学：三种访存模式¶

CUDA 的设计哲学可以用一句话概括：

"在 GPU 眼里，只有三种访存模式"

模式 本质 对应算子
Map 你只管怎么算，不管邻居 Elementwise, Gather
Reduce 你得把邻居的值拿过来合并 Reduce, Scan（部分）
Stencil 你得拿固定邻居的值 Stencil/Conv

表格里的 MatMul、Conv、Gather 本质上都是在"如何把数据搬到 Shared Memory 里"的不同包装。当你掌握了这三种模式，你就掌握了 GPU 编程的底层思维。

从 Shader 思维到 CUDA 思维¶

过去写 Shader 现在写 CUDA Kernel
float4 color = tex2D(...) float data = input[threadIdx.x + blockIdx.x * blockDim.x]（Gather）
SV_Target 输出结果 output[idx] = data（Scatter）
[numthreads(8,8,1)] 分块处理纹理 blockDim.x + __shared__ 分块加载数据（Tiled）
关心纹理 Cache 命中率 关心 Global Memory 的 Coalesced Access + Shared Memory Bank Conflict
discard 跳过像素 if(condition) return;（注意 Warp 发散）

算子难度阶梯（从 Shader 背景过渡）¶

难度 类别 代表操作 核心挑战
⭐ Elementwise ReLU, Add, Mul 无通信，无同步——直接平移 Pixel Shader 思维
⭐⭐ Reduce Sum, Max, Mean 规则通信（树形），需 __syncthreads
⭐⭐⭐ Scan CumSum, Prefix 规则通信 + 数据依赖链
⭐⭐⭐⭐ Gather/Scatter Embedding 不规则访问，Cache Miss，无法预取
⭐⭐⭐⭐⭐ Stencil/Conv Conv2d, Pooling Tiling + 边界 Halo + 循环嵌套
⭐⭐⭐⭐⭐⭐ GEMM/MatMul Linear, Attention Tiling + Tensor Core + 布局优化

你作为图形工程师在哪层最占优势？

  1. Stencil/Conv 和你写 Tiled Deferred Shading 几乎一模一样——分块加载，处理邻居数据，处理边界
  2. Reduce/Scan 很像在 Compute Shader 里写 Mipmap 生成——有同步但规则
  3. GEMM 是最难的，但你已经有了分块、双缓冲、Shared Memory 的思维基础，只是多了 Tensor Core 指令

从 Stencil 无缝切入，向 GEMM 发起总攻——这是你的最佳路线。"
