1.3 GPU 存储层次: HBM → L2 → Shared Memory → Register¶

概述¶

GPU 的存储层次从慢到快、从大到小依次为：HBM（显存）→ L2 Cache → L1 Cache / Shared Memory → Register。

搞渲染的你最清楚：数据在哪层决定了访问速度。AI 推理优化的本质，就是让数据尽量呆在离计算单元近的存储层级里。

GPU 存储层次全景（以 A100 为例）¶

下表用于建立数量级直觉。延迟和有效带宽会随访问模式、指令、争用和具体 GPU 型号变化，不是 CUDA 保证的固定常数。

存储层级 硬件本质 A100 典型容量 延迟特征 谁控制
HBM（显存） DRAM 40/80 GB 最高 软件分配，硬件访问
L2 Cache SRAM 40 MB（整卡共享） 高于片上 SM 存储 硬件自动管理，可用策略提示影响
L1 / Shared 统一数据存储 SRAM 192 KB/SM，总分区受架构与配置约束 低 L1 由硬件管理；Shared 由程序显式寻址
Register File 专用片上存储 64K 个 32-bit 寄存器/SM 最低，但也受依赖和端口限制 编译器分配 
flowchart LR
    HBM["HBM / Global Memory<br/>容量最大"] --> L2["L2 Cache<br/>整卡共享"]
    L2 --> L1["L1 Cache<br/>每 SM"]
    L2 --> SMEM["Shared Memory<br/>每 Block 显式管理"]
    L1 --> REG["Registers<br/>每线程"]
    SMEM --> REG

存储层次的本质：SRAM vs DRAM¶

所有片上存储（L1、L2、Shared Memory、Register）都是 SRAM（静态随机存取存储器），而 HBM 是 DRAM（动态随机存取存储器）。

关键区别：

SRAM：速度快、容量小、功耗高、成本高——用于片上缓存 DRAM：速度慢、容量大、功耗低、成本低——用于主存（显存）

但有一个最常见的误解需要澄清：

Shared Memory 不是 Cache。在许多 NVIDIA 架构上，它和 L1 使用统一的片上数据存储资源，但地址空间、访问指令和管理方式不同。

Shared Memory vs L1 Cache：核心区别¶

这是 GPU 存储层次中最关键、也最容易混淆的区别。

维度 L1 Cache Shared Memory
管理方式 硬件自动管理：决定缓存什么、淘汰什么 软件显式管理：你手动 Load/Store
可预测性 尽力而为：缓存可能命中或被替换 显式生命周期：写入后由程序决定何时复用，仍要考虑同步、Bank Conflict 和容量
用途 透明加速 Global Memory 访问 同一 Block 内线程共享数据，手动 Tiling
控制粒度 你无法控制（硬件决定） 完全控制（你决定何时加载、何时同步）
性能约束 命中率、Cache Line 利用率、争用 Bank Conflict、同步、占用率、访问吞吐

用你的渲染语言翻译：

L1 Cache = 硬件管理的临时副本；它不是由驱动逐次决定装入和淘汰。 Shared Memory = 你自己定义的 groupshared 变量——你显式声明大小，手动 Load/Store，完全掌控。

物理共享的 SRAM¶

在 A100 上，每个 SM 有 192 KB 的统一 L1/Texture/Shared 数据存储资源，单个 Block 可用的 Shared Memory 和可选 carveout 有额外上限。不同架构的容量和分区选项不同，优化时应查询设备属性，而不是把某一代 GPU 的数字写死到 Kernel 假设中。

DX12 Heap 与缓存的类比只适合记忆“显式控制和自动管理”的差别：Shared Memory 是线程块可寻址的 Scratchpad，而 Heap 是全局显存分配对象，两者并不处于同一存储层级。

Cache 与 Shared Memory 如何协作？¶

图形和 AI 都会同时利用 Cache、寄存器和显式 Scratchpad。真正的选择依据是访问模式与复用范围，而不是工作负载名称。

图形渲染：纹理采样的可预测性¶

在 Pixel Shader 中执行 tex2D 时：

  1. 相邻像素几乎总是采样相邻纹素（空间局部性）
  2. 纹理布局和采样器会改善二维局部性与过滤访问
  3. Cache 命中率仍取决于纹理尺寸、采样模式、各向异性和工作集
  4. Compute Shader 也常用 groupshared 做 Tiled/Clustered Shading、滤波和归约

AI 推理：规则访问与显式复用¶

高性能 GEMM、Conv 和 Attention 的地址通常很规则，L1/L2 仍然重要。Shared Memory 的价值在于把跨线程复用和数据布局显式化：

  1. GEMM / Attention：协作式加载连续 Tile，再在 Block 内复用同一批元素。
  2. Conv2d：权重的数值是否随机与地址局部性无关；布局、步幅和 Tile 决定访存效率。
  3. Embedding / MoE Scatter：这类不规则访问更依赖 L2、合并请求、排序和数据重排，Shared Memory 并不能自动消除随机性。

核心结论：Cache 捕获跨 Block 或难以显式安排的局部性；Shared Memory 为 Block 内已知的复用和布局变换提供可编程空间。二者通常协作，而不是二选一。

用你的渲染语言翻译¶

场景 图形纹理采样 AI 数据加载
你的代码 float4 c = tex2D(tex, uv); float d = __ldg(&data[ idx ]);
谁管缓存 TMU + Cache（硬件） 你自己（软件）
访问模式 相邻像素采相邻纹素 → 可预测 跨步/随机 → 不可预测
Cache 表现 取决于采样工作集和布局 取决于算子布局、批量和复用距离
常见优化 纹理布局、Pass 合并、groupshared Tiling 合并访问、__shared__ Tiling、布局重排与融合

存储层次与 AI 优化策略¶

优化技术 涉及哪些存储层级 本质
算子融合 HBM（减少读写）→ L1/L2（减少搬运） 减少中间结果在 HBM 的读写次数
Tiling（分块） HBM → Shared Memory → Register 把数据从 HBM 搬进 SRAM，利用片上高速缓存
INT8 量化 HBM（减半数据量） 减少从 HBM 搬运的数据量
FlashAttention HBM → Shared Memory（Online Softmax） 中间矩阵 S=Q×K^T 不写回 HBM
Warp Shuffle Register（零 SRAM 开销） 寄存器级数据交换，不经过 Shared Memory

选择依据¶

图形渲染：Cache 是"高速路旁的加油站"，你开过去的时候（采样纹理），顺便加油（缓存命中）。 AI 推理：Shared Memory 是你自己买的"私人停车场"，你提前把车（数据）都停进去，然后工人（线程）可以零距离随便拿。

如果你的项目是... 你应该优先考虑...
工作集跨多个 Block 复用或复用关系不易显式安排 优先改善布局与 Cache Line 利用率
同一 Block 内有明确、密集的重复读取 用 Shared Memory 建立 Tile
Warp 内少量标量交换或归约 优先考虑 Shuffle 和寄存器
数据几乎只读一次 避免为了“使用 Shared Memory”而增加搬运与同步

最终用 Nsight Compute 的全局内存吞吐、L1/L2 命中、Shared Memory 冲突和 Stall 指标验证选择；不能仅凭“图形”或“AI”标签判断。
