4.2 分块 (Tiling) 与局部性：从访问模式推导 Tile¶

概述¶

Tiling（分块） 是 GPU 计算中最核心的局部性优化技术。图形与 AI 并不存在“图形一定多 Pass、AI 一定单 Pass”的边界：两者都可能在一个线程组内使用片上 Tile，也都可能因为全局依赖、容量或调度边界拆成多个 Pass/Kernel。

  • 线程块内 Tiling：把可复用数据搬到 groupshared / Shared Memory，在同步范围内复用。
  • 跨 Pass / Kernel 分解：把无法放进同一同步域或可分解的工作拆开，中间结果写回全局内存。

选择由数据依赖、复用次数、片上容量、并行度和融合代价共同决定。

核心问题：AI 做 Tiling 的对象是什么？¶

矩阵乘和直接卷积通常同时对输入与权重分块，但并非每个 AI 算子都如此。Elementwise 往往不需要 Shared Memory；Embedding/Gather 的关键可能是请求排序和 Cache；不同卷积算法也可能隐式变换或直接计算。

Tiling 对象 为什么需要 加载到哪里
输入特征图 (Input Activation) 太大，一次装不进 Shared Memory Shared Memory Tile
权重 (Weight) 太大，一次装不进 Shared Memory Shared Memory Tile
两者同时 因为两者在计算中都有高复用率 同时加载到 Shared Memory 做矩阵乘

判断方法：先写出一个输出 Tile 依赖哪些输入，再统计每个输入元素在该线程块内会复用多少次。只有复用收益大于搬运、同步和占用率代价时，才值得放进 Shared Memory。

为什么不像图形那样只 Tiling 输入？¶

场景 复用的数据 为什么
图形模糊（3×3 高斯） 输入像素 同一个输入像素会被相邻像素的窗口反复用到
AI 卷积（C_in=128, C_out=256） 权重和输入同时复用 同一个权重会被所有输入位置用到；同一个输入位置也会被所有输出通道用到

在 AI 中，输入和权重的复用关系是双向的，所以必须同时加载两者。

算术强度：重要但不是唯一指标¶

算术强度（Arithmetic Intensity）= 执行的运算量 / 从目标存储层级搬运的字节数，常用单位是 FLOP/byte。分母必须按“唯一搬运字节”与实际复用计算，不能把循环次数直接当成每个元素的复用次数。

场景 典型特征 常见策略 仍需验证
图形模糊（3×3） 邻域重叠，输入像素被多个输出复用 Texture Cache 或 groupshared Halo Tile 工作集、边界处理、分辨率
可分离高斯模糊 二维核可写成两个一维核 水平、垂直两 Pass 中间写回是否小于少采样收益
GEMM / 直接卷积 输入与权重在两个输出维度上复用 多级 Tiling 到 Shared Memory 和寄存器 Tile 尺寸、占用率、Tensor Core 布局
Decode GEMV 权重通常只被少量 token 复用 合并请求、量化、向量化读取 Batch 大小时是否转为 GEMM

Roofline 可用算术强度初步判断带宽上限和计算上限，但分支、延迟、占用率、指令吞吐和通信也可能成为瓶颈。

多 Pass 的典型理由：算法可分解¶

高斯模糊常拆成水平与垂直 Pass，直接原因是高斯核可分离：

5×5 高斯核：
  不拆：每个像素读 25 次纹理 → 25 次访存
  拆开（水平+垂直）：每个像素读 5 + 5 = 10 次纹理 → 省掉 60% 带宽

这里减少的是每个输出的采样/乘加次数，同时增加一次中间图像的写回和读取。是否更快取决于核尺寸、Cache、分辨率和 Pass 开销。

单 Kernel Tiling 的典型理由：片上复用¶

GEMM 与许多卷积实现把输入和权重 Tile 协作式加载到片上存储，使一次全局内存读取服务多个输出。Tiling 主要减少重复搬运，不会减少数学定义要求的乘加次数。

AI 卷积的 Tiling：
  不 Tiling：每次计算都要从 HBM 读权重 → 带宽爆炸
  Tiling：把权重块 + 输入块加载到 Shared Memory → 只读一次，反复复用

收益大小由 Tile 内实际复用次数决定，代价包括 Shared Memory 容量、同步、寄存器压力和可能下降的 Occupancy。

图形多 Pass vs AI 单 Pass Tiling：完整对比¶

维度 图形（高斯模糊） AI（Conv2d）
算法性质 某些滤波核可分离；也有不可分离滤波 训练权重通常不可直接按空间核分离，但可使用低秩、Winograd、FFT 或 implicit GEMM 等算法
主要瓶颈 可能是采样、带宽、填充率或 ALU 随算子与形状变化，可能是计算、带宽、延迟或通信
Pass / Kernel 边界 由算法分解、资源状态和同步范围决定 由融合收益、全局同步、动态形状和资源预算决定
Shared Memory 用法 Tiled/Clustered Shading、滤波、直方图等常用 GEMM/Conv/Attention 常用；Elementwise 未必需要
共同目标 提高局部性，减少无效搬运，同时保留足够并行度 提高局部性，减少无效搬运，同时保留足够并行度

为什么 Shared Memory 能装下大纹理？¶

你可能会问：Shared Memory 只有几十 KB，怎么装得下一整张纹理？

答案：Shared Memory 不是装整张图，而是只装当前 Tile 需要的那一小块。

比如 Conv2d 的 Tiling：

输入特征图（H×W×C_in）        权重（C_out×C_in×K×K）
┌─────────────────────┐       ┌─────────────────────┐
│  Tile 1 │ Tile 2 │ ...      │  Tile 1 │ Tile 2 │ ...
│─────────┼─────────┤        │─────────┼─────────┤
│  Tile 3 │ Tile 4 │ ...      │  Tile 3 │ Tile 4 │ ...
└─────────────────────┘       └─────────────────────┘
          │                            │
          └───────── Load ─────────────┘
                      │
                     ▼
          ┌─────────────────────┐
          │   Shared Memory     │ ← 输入 Tile + 权重 Tile 同时在这里
          │   (片上 SRAM, 极快)  │
          └─────────────────────┘
                      │
                     ▼
          ┌─────────────────────┐
          │   Tensor Core       │ ← 在片上做矩阵乘
          │   (一次性算完一块)    │
          └─────────────────────┘

每次只加载一个 Tile，算完再加载下一个。Shared Memory 装不下整张图，但装得下当前线程块正在处理的那一个 Tile。

AI 做 Tiling 的本质¶

Tiling 的本质是把一个大迭代空间映射到分层存储和分层并行结构。

它不会替代 Cache 或 TMU，而是在已知复用模式下补充硬件自动缓存。一个高性能 Kernel 往往同时依赖 L2、L1、Shared Memory、寄存器和专用矩阵指令。

高效 Tiling 的四条铁律¶

铁律 具体做法 图形经验
1. 合并访问 加载时让连续线程访问连续地址（Coalesced Access） 让相邻像素采相邻纹素
2. 避免 Bank Conflict 根据实际 Warp 访问方向使用 Padding 或 Swizzle 与 Race Condition 不同；HLSL groupshared 也有 Bank 布局问题
3. 循环展开 #pragma unroll 手动展开内层循环 减少循环控制开销
4. 双缓冲 计算当前 Tile 时，后台异步加载下一个 Tile 三重缓冲思想平移

最终结论¶

场景 优化策略 本质原因
算法可分离，拆分后显著减少工作量 多 Pass / 多 Kernel 以中间写回换更少的总计算或采样
Block 内存在明确数据复用 Shared Memory / Register Tiling 以显式搬运和同步换更少的全局内存流量
融合导致寄存器或 Shared Memory 压力过高 保留 Kernel 边界 避免 Spill 和 Occupancy 过低
复用很低或 Cache 已足够 直接访问 避免无收益的片上搬运

最终策略应由 Roofline、时间线和 Kernel 指标共同验证，而不是由“图形”或“AI”的类别预先决定。
