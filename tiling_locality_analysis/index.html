4.2 分块 (Tiling) 与局部性: 为何图形做多 Pass，AI 做单 Pass Tiling

概述

Tiling（分块） 是 GPU 计算中最核心的局部性优化技术。但图形渲染和 AI 推理在使用 Tiling 时，走了两条完全不同的路：

  • 图形：多 Pass（每 Pass 处理一小块，Pass 间通过 RT 切换同步）
  • AI：单 Pass + Shared Memory Tiling（一个 Kernel 内循环加载多个 Tile）

理解这背后的原因，你就理解了图形和 AI 在 GPU 上的本质差异。

核心问题：AI 做 Tiling 的对象是什么？

AI 做 Tiling 时，同时对输入特征图和权重进行分块加载，而不是只对某一个。

Tiling 对象 为什么需要 加载到哪里
输入特征图 (Input Activation) 太大，一次装不进 Shared Memory Shared Memory Tile
权重 (Weight) 太大，一次装不进 Shared Memory Shared Memory Tile
两者同时 因为两者在计算中都有高复用率 同时加载到 Shared Memory 做矩阵乘

你的理解：AI 做 Tiling，就是把\"输入块\"和\"权重块\"一起搬进 Shared Memory，然后像做矩阵乘一样，在片上把计算全部摊平。

为什么不像图形那样只 Tiling 输入？

场景 复用的数据 为什么
图形模糊（3×3 高斯） 输入像素 同一个输入像素会被相邻像素的窗口反复用到
AI 卷积（C_in=128, C_out=256） 权重和输入同时复用 同一个权重会被所有输入位置用到；同一个输入位置也会被所有输出通道用到

在 AI 中，输入和权重的复用关系是双向的，所以必须同时加载两者。

算访比：决定一切的核心指标

算访比（Compute-to-Access Ratio）= 每读一个数据，你要做多少次计算操作。

场景 每读一个元素，做多少次计算 算访比 是否值得 Tiling
图形模糊（3×3） 读 9 次像素，算 9 次乘加 ≈1 ❌ 不值得
AI 卷积（3×3, C_in=64, C_out=128） 读一个像素，做 64×128×9 次乘加 ≈73728 ✅ 极其值得！

你的直觉：算访比决定了你是\"带宽瓶颈\"还是\"算力瓶颈\"。算访比低 → 带宽是瓶颈（图形）；算访比高 → 算力是瓶颈（AI）。

图形：算访比低 → 多 Pass 省带宽

图形模糊（如高斯模糊）的算访比 ≈ 1，意味着：

  • 瓶颈在 TMU（纹理采样太慢）
  • 每读一次纹理数据，只做一次乘加
  • 所以宁可多开一个 Pass，也要减少纹理采样次数

这就是为什么图形模糊要拆成水平 + 垂直两个 Pass：

5×5 高斯核：
  不拆：每个像素读 25 次纹理 → 25 次访存
  拆开（水平+垂直）：每个像素读 5 + 5 = 10 次纹理 → 省掉 60% 带宽

收益：访存减少 60%，代价是多一次 RT 切换（图形中 RT 切换的开销相对较小）。

AI：算访比高 → 单 Pass Tiling 省算力

AI 卷积（以 C_in=64, C_out=128, 3×3 为例）的算访比 ≈ 73728，意味着：

  • 瓶颈在 Tensor Core（计算太快，数据喂不饱）
  • 每读一次数据，要做七万多次乘加
  • 所以宁可一次把所有数据读到 Shared Memory，也要减少重复访存
AI 卷积的 Tiling：
  不 Tiling：每次计算都要从 HBM 读权重 → 带宽爆炸
  Tiling：把权重块 + 输入块加载到 Shared Memory → 只读一次，反复复用

收益：访存减少几十万倍，代价是手动写 Tiling 逻辑。

图形多 Pass vs AI 单 Pass Tiling：完整对比

维度 图形（高斯模糊） AI（Conv2d）
卷积核是否可分离 ✅ 是（高斯核 = h × v） ❌ 否（训练得到的随机权重）
主要瓶颈 纹理采样（带宽） 算力 + 带宽（Tensor Core 太快）
为什么拆/不拆 拆了采样从 25 降到 10 次，值 拆了计算量翻倍 + 带宽翻倍，血亏
Shared Memory 用法 无所谓（纹理 Cache 自动搞定） 必须手动 Tiling（显式加载权重 + 输入）
优化方向 减少纹理采样次数 减少 Global Memory 访问 + 增加计算密度

为什么 Shared Memory 能装下大纹理？

你可能会问：Shared Memory 只有几十 KB，怎么装得下一整张纹理？

答案：Shared Memory 不是装整张图，而是只装当前 Tile 需要的那一小块。

比如 Conv2d 的 Tiling：

输入特征图（H×W×C_in）        权重（C_out×C_in×K×K）
┌─────────────────────┐       ┌─────────────────────┐
│  Tile 1 │ Tile 2 │ ...      │  Tile 1 │ Tile 2 │ ...
│─────────┼─────────┤        │─────────┼─────────┤
│  Tile 3 │ Tile 4 │ ...      │  Tile 3 │ Tile 4 │ ...
└─────────────────────┘       └─────────────────────┘
          │                            │
          └───────── Load ─────────────┘
                      │
                     ▼
          ┌─────────────────────┐
          │   Shared Memory     │ ← 输入 Tile + 权重 Tile 同时在这里
          │   (片上 SRAM, 极快)  │
          └─────────────────────┘
                      │
                     ▼
          ┌─────────────────────┐
          │   Tensor Core       │ ← 在片上做矩阵乘
          │   (一次性算完一块)    │
          └─────────────────────┘

每次只加载一个 Tile，算完再加载下一个。Shared Memory 装不下整张图，但装得下当前线程块正在处理的那一个 Tile。

AI 做 Tiling 的本质

AI 做 Tiling，本质上就是在用软件写一个\"纹理采样器\"的替代品。

你不再依赖硬件 TMU 和 Cache，而是自己写一套加载、缓存、复用的逻辑，来应对\"不可预测的访问模式\"。

高效 Tiling 的四条铁律

铁律 具体做法 图形经验
1. 合并访问 加载时让连续线程访问连续地址（Coalesced Access） 让相邻像素采相邻纹素
2. 避免 Bank Conflict Shared Memory 做 Padding（[32][33] 替代 [32][32]） 避免 groupshared Race Condition
3. 循环展开 #pragma unroll 手动展开内层循环 减少循环控制开销
4. 双缓冲 计算当前 Tile 时，后台异步加载下一个 Tile 三重缓冲思想平移

最终结论

场景 优化策略 本质原因
图形渲染（算访比低） 多 Pass 换少采样 带宽是瓶颈，宁可多 Pass 也要少访存
AI 推理（算访比高） 单 Pass + Tiling 算力是瓶颈，宁可多加载也要少重复计算

你已经完全可以这样理解：图形优化是\"我怎么才能少读点纹理？\"，AI 优化是\"我怎么才能让 Tensor Core 多干点活，少等数据？\"。
