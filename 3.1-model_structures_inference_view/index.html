3.1 模型结构速览 (YOLOv8, Transformer 的推理视角)¶

概述¶

在图形渲染中，你习惯把渲染管线拆成一系列 Pass：先画 G-Buffer，再算光照，最后做后处理。AI 推理模型也是同样的思路——它是一个固定的数据流水线，输入经过一系列计算变换，最终输出结果。

本文从推理视角（而非训练视角）速览两种主流模型结构：YOLOv8（视觉检测）和 Transformer（大语言模型）。重点不在于记住每一层的名字，而在于理解数据在 GPU 上的流动方式。

核心思维：当你把模型结构拆解成 GPU 数据流时，你看到的不再是"神经网络层"，而是 Kernel Launch 序列 + 显存读写模式。

一、YOLOv8 模型结构¶

YOLOv8 延续了 YOLO 系列的经典三段式设计：Backbone（主干网络）→ Neck（颈部网络）→ Head（检测头）。

整体数据流¶

640×640×3 → Backbone 逐级下采样 → Neck 多尺度融合 → Head 输出 3 个尺度的预测结果

1. Backbone：特征提取¶

Backbone 的作用是从输入图像中提取特征。它由 5 个 Stage 组成，每个 Stage 以一个步长为 2 的卷积开始进行下采样，后面接 C2f 模块，最后用 SPPF 融合多尺度特征。

Stage 输入尺寸 操作 输出尺寸
输入 640×640×3 Conv (3×3, stride=2, 32 filters) 320×320×32
Stage 1 320×320×32 Conv stride=2 → C2f 160×160×64
Stage 2 160×160×64 Conv stride=2 → C2f 80×80×128
Stage 3 80×80×128 Conv stride=2 → C2f 40×40×256
Stage 4 40×40×256 Conv stride=2 → C2f 20×20×512
Stage 5 20×20×512 Conv stride=2 → SPPF 10×10×512

关键模块：

  • C2f：取代了 YOLOv5 的 C3 模块。结构更轻量，增强了梯度流（训练时），在推理时是一个高效的特征提取块。它将输入分成两个分支，通过多个 Bottleneck 增强梯度流。

  • SPPF (Spatial Pyramid Pooling - Fast)：用三个级联的 5×5 最大池化，等效于一个多尺度金字塔池化，在不增加计算量的前提下大幅提升感受野。相比于 SPP，SPPF 将三个池化串联（而非并联），计算量更小。

GPU 视角：Backbone 的每一层输出尺寸在缩小、通道在增加。这是一个典型的访存密集型 → 计算密集型的过渡过程——早期 Stage 的特征图大通道少（访存瓶颈），后期 Stage 特征图小通道多（计算瓶颈）。

2. Neck：特征融合 (PAN-FPN)¶

Neck 使用 PAN-FPN 结构，通过自顶向下和自底向上的双向路径，让深层语义信息和浅层细节信息充分融合。

自顶向下（FPN — 特征金字塔）：

10×10×512 → 上采样 → 与 Stage4(20×20×512) 拼接 → C2f → 20×20×512
20×20×512 → 上采样 → 与 Stage3(40×40×256) 拼接 → C2f → 40×40×256

自底向上（PAN — 路径聚合网络）：

40×40×256 → 下采样 → 与 FPN(20×20×512) 拼接 → C2f → 20×20×512
20×20×512 → 下采样 → 与 FPN(10×10×512) 拼接 → C2f → 10×10×512

Neck 输出的三个特征图：

特征图 尺寸 负责检测
P3 80×80×256 小目标
P4 40×40×512 中目标
P5 20×20×512 大目标

GPU 视角：Neck 阶段涉及上采样、拼接、C2f 等操作。拼接在 GPU 上只是内存视图的重新解释，不需要实际拷贝数据——这是融合策略中可以利用的优化点。

3. Head：检测头输出¶

YOLOv8 的检测头有两大革新：

  • Anchor-Free（无锚框）：直接预测目标的中心点和宽高，省去复杂的锚框调参。
  • Decoupled Head（解耦头）：分类和回归任务拆分到两个独立分支，避免相互干扰，提升精度。

每个尺度对应的输出：

                     ┌──────────────────┐
P3/P4/P5 ──────────►│  分类分支 (Cls)  │──► H × W × 80 (类别概率)
                     ├──────────────────┤
                     │  回归分支 (Reg)  │──► H × W × 4 (边界框偏移 + 宽高)
                     └──────────────────┘

GPU 视角：Head 是典型的 Elementwise 操作，每个网格独立计算。分类用 Sigmoid，回归用某种激活函数。这一阶段是访存密集型——计算量不大，但每个网格都要读写显存。

GPU 流水线视角下的 YOLOv8¶

对于推理优化工程师，YOLOv8 的推理就是一条确定的 GPU Kernel 流水线：

// 伪代码：YOLOv8 推理的 Kernel Launch 序列
// 每个 Launch 对应一个 GPU Kernel

// Backbone
conv_kernel<<<grid, block>>>(input, weight1, conv1_out);       // Conv1
c2f_kernel<<<grid, block>>>(conv1_out, weight2, c2f_out);      // C2f Stage1
// ... 重复 Conv + C2f 直到 Stage4
sppf_kernel<<<grid, block>>>(stage4_out, sppf_weight, sppf_out); // SPPF

// Neck (PAN-FPN)
upsample_kernel<<<grid, block>>>(sppf_out, up_out);            // 上采样
concat_kernel<<<grid, block>>>(up_out, stage4_out, cat_out);   // 拼接
c2f_kernel<<<grid, block>>>(cat_out, weight, fpn_out);         // FPN C2f
// ... PAN 路径类似

// Head (Decoupled)
conv_kernel<<<grid, block>>>(pan_out, cls_weight, cls_out);    // 分类分支
conv_kernel<<<grid, block>>>(pan_out, reg_weight, reg_out);    // 回归分支

YOLOv8 推理流水线类比图形 Pass： - Backbone = 一系列逐渐降低分辨率的 Pass（像 Mipmap 生成） - Neck = 多 Pass 融合（像 HDR 合并 + Tone Mapping） - Head = 最终输出 Pass（像 Render Target 输出到屏幕）

二、Transformer 模型架构¶

Transformer 是当前大语言模型（LLM）的核心架构。从推理视角看，它是一系列固定层的重复堆叠，每层结构完全相同。

单层 Transformer Block 数据流¶

输入张量 (Batch, SeqLen, HiddenDim)

    ▼
┌────────────────────────────────────┐

│          QKV 投影                   │  ← 矩阵乘 (3 组 Linear)，Tensor Core
│          [B,S,H] × [H,3H]          │

│          RoPE (旋转位置编码)         │  ← 逐元素旋转操作

┌────────────────────────────────────┐
│          Self-Attention             │  ← Q×K^T → Softmax → ×V

模块拆解¶

1. Embedding（嵌入层）¶

将 token ID 映射为稠密向量。本质是一个 Gather 操作——根据 token ID 从权重矩阵中取对应的行。

输入形状: [Batch, SeqLen] (token ID 序列)
输出形状: [Batch, SeqLen, Dim]
权重形状: [VocabSize, Dim]

GPU 视角：Gather 是不规则访存——相邻的 token ID 不一定对应连续的权重行。缓存命中率取决于访问模式的局部性。

2. QKV 投影 + RoPE¶

  • QKV 投影：将输入通过三个独立的 Linear 层（矩阵乘）映射到 Query、Key、Value 空间。这是计算密集型操作，由 Tensor Core 加速。
  • RoPE：在 Q 和 K 上注入位置信息，通过旋转角度实现。轻量的逐元素三角函数操作，由 CUDA Core 处理。

3. Self-Attention（自注意力）¶

Attention 的计算公式：

Attention(Q, K, V) = softmax(Q × K^T / √d) × V

标准 Attention 的 GPU 执行流程（暴露带宽瓶颈）：

Step 1: S = Q × K^T        // [B, H, S, d] × [B, H, d, S] → [B, H, S, S]
                            // 矩阵乘，Tensor Core。结果必须写回显存！
                            ↓
Step 2: P = softmax(S)      // 从显存读 S，写回 P（两次显存访问）
                            ↓
Step 3: O = P × V           // [B, H, S, S] × [B, H, S, d] → [B, H, S, d]
                            // 矩阵乘，Tensor Core

问题：中间矩阵 S = Q × K^T（尺寸 S×S）必须完整写回显存再读出来。当序列长度 S 变大时（如 4096、8192），这个中间矩阵的显存读写成为主要瓶颈。

FlashAttention 的解决思路：通过 Tiling + Online Softmax，把中间矩阵 S 留在片上 SRAM（Shared Memory）中，不写回显存。

GPU 视角：Attention 在 Decode 阶段，Q 只有一个 token（S=1），而 K 和 V 是完整的 KV Cache。此时 Attention 退化为一个 GEMV（矩阵-向量乘），访存带宽成为瓶颈。

KV Cache：推理时缓存历史 K 和 V，避免重复计算。这跟你图形渲染中的"帧缓存"是同样的思想——把之前算好的结果存起来，下次直接用。

4. FFN（前馈网络）¶

标准的 FFN 包含两个线性层和一个激活函数：

FFN(x) = W₂ × GELU(W₁ × x)
  • 第一层：从 Dim 扩展到 4×Dim（或更高）
  • 激活函数：GELU / SiLU（非线性的 Elementwise 操作）
  • 第二层：从 4×Dim 压缩回 Dim

GPU 视角：FFN 的两个线性层是计算密集型的 GEMM，由 Tensor Core 加速。激活函数由 CUDA Core 处理。FFN 是 Transformer 推理中计算量占比最高的部分（约 2/3）。

5. RMSNorm / LayerNorm¶

RMSNorm(x) = x / sqrt(mean(x²) + ε) × γ

GPU 视角：RMSNorm 包含一个 Reduce（求平方的均值） 和一个 Elementwise（归一化）。它涉及一次全局内存的读取和写入，是访存密集型操作。

Transformer 推理的 GPU 流水线特征¶

以 LLM 的 Decode 阶段为例，每生成一个 Token，要依次跑：

RMSNorm → QKV 投影 → RoPE → Attention → 残差连接 → FFN → ...

未融合实现可能包含十几到几十个 Kernel。单次 Launch 延迟与系统、软件栈和测量方法相关，通常是微秒量级；小 Kernel 中占比更明显。

关键差异（对比图形渲染）：

特征 图形渲染 Transformer 推理
任务粒度 既有大型 Draw，也有短 Compute/Copy 随 Batch、序列与融合程度变化
Kernel 数量 少（几十到几百） 多（几十到几百，但每个计算量小）
数据依赖 Pass 间常有显式资源依赖 层内/层间有张量依赖
提交开销占比 取决于 Draw/Dispatch 粒度 小 Batch Decode 中可能较高
能否重叠 可做帧级与异步队列重叠 可做请求、流水线、通信/计算重叠，但受依赖限制

这解释了两类不同优化：CUDA Graph 保留多个 Kernel 节点但降低重复提交开销；算子融合 才会把多个操作合入更少的 Kernel，以减少 Launch 和中间张量流量。两者都需要评估动态形状、寄存器压力和可维护性。

三、总结对比¶

维度 YOLOv8 Transformer (Decoder Layer)
整体结构 Backbone → Neck → Head RMSNorm → Attention → FFN → Residual
数据流形式 串行，每个 Stage 产出多尺度特征 串行，每一步依赖上一步输出
计算密集阶段 Conv 层（Backbone） QKV 投影、FFN（Tensor Core）
访存密集阶段 Concat、Head 输出 RMSNorm、残差连接、Softmax
主要瓶颈 卷积层的计算密度 Attention 的中间矩阵显存读写
优化方向 算子融合、INT8 量化 FlashAttention、算子融合、KV Cache

一句话总结：图形渲染是"游击战"（状态多变，需要快速应变），AI 推理是"阅兵式"（流程固定，所以能极致优化）。
