11.3 PagedAttention 实战：DX12 与 TensorRT 双后端¶

实战范围¶

本篇实现一个用于理解分页 KV Cache 的简化 Decode Attention：

  • FP16 K/V，FP32 累加；
  • 每个请求本步一个 Query Token；
  • 支持不同 context_len；
  • 支持 GQA；
  • KV Cache 使用固定大小的物理 Block；
  • CPU 维护 Block Table，GPU 根据页表读取非连续 K/V；
  • 提供 DX12/HLSL 原型和 TensorRT/CUDA Plugin 两个后端。

DX12 与 TensorRT 是两个不同执行生态。本文让它们共享数据契约、CPU Reference 和测试向量，但不假设 DX12 Resource 能被 TensorRT 直接绑定。跨 API 零拷贝需要 CUDA-D3D12 External Memory、同步句柄和平台支持，超出简化实现范围。

一、先定义后端无关的数据契约¶

1. 张量与页表¶

Q              [batch, num_q_heads, head_size]
KCache/VCache  [num_blocks, block_size, num_kv_heads, head_size]
BlockTable     [batch, max_blocks_per_seq]
ContextLens    [batch]
Output         [batch, num_q_heads, head_size]

逻辑位置到物理位置：

logical_block = token_pos / block_size;
offset        = token_pos % block_size;
physical      = block_table[batch_id * max_blocks + logical_block];
slot          = physical * block_size + offset;

GQA Head 映射：

group_size = num_q_heads / num_kv_heads;
kv_head = q_head / group_size;

2. 参数结构¶

struct PagedAttentionParams {
    uint32_t batch_size;
    uint32_t num_q_heads;
    uint32_t num_kv_heads;
    uint32_t head_size;
    uint32_t block_size;
    uint32_t max_blocks_per_seq;
    float scale;
};

校验项：

  • num_q_heads % num_kv_heads == 0；
  • context_len <= max_blocks_per_seq * block_size；
  • 所有有效 Block ID 位于 [0, num_blocks)；
  • Buffer Size 满足 Shape 与数据类型要求；
  • HLSL Constant Buffer 布局与 C++ 端 16 字节对齐一致；
  • TensorRT Plugin 的输入类型与 Format 组合受支持。

二、CPU Reference：先验证页表，再验证 Attention¶

size_t kv_index(
    int block_id, int offset, int kv_head, int d,
    int block_size, int num_kv_heads, int head_size)
{
    return (((size_t)block_id * block_size + offset) * num_kv_heads + kv_head)
           * head_size + d;
}

void paged_attention_ref(
    const float* q, const float* k_cache, const float* v_cache,
    const int32_t* block_table, const int32_t* context_lens,
    float* output, const PagedAttentionParams& p)
{
    for (int b = 0; b < p.batch_size; ++b) {
        for (int qh = 0; qh < p.num_q_heads; ++qh) {
            const int kvh = qh / (p.num_q_heads / p.num_kv_heads);
            std::vector<float> scores(context_lens[b]);
            float row_max = -INFINITY;

            for (int t = 0; t < context_lens[b]; ++t) {
                int logical_block = t / p.block_size;
                int offset = t % p.block_size;
                int block_id = block_table[b * p.max_blocks_per_seq + logical_block];
                float score = 0.0f;
                for (int d = 0; d < p.head_size; ++d) {
                    size_t ki = kv_index(block_id, offset, kvh, d,
                                         p.block_size, p.num_kv_heads, p.head_size);
                    score += q[(b * p.num_q_heads + qh) * p.head_size + d] * k_cache[ki];
                }
                scores[t] = score * p.scale;
                row_max = std::max(row_max, scores[t]);
            }

            float denominator = 0.0f;
            for (float& score : scores) {
                score = std::exp(score - row_max);
                denominator += score;
            }

            float* out = output + (b * p.num_q_heads + qh) * p.head_size;
            std::fill(out, out + p.head_size, 0.0f);
            for (int t = 0; t < context_lens[b]; ++t) {
                int lb = t / p.block_size;
                int off = t % p.block_size;
                int block_id = block_table[b * p.max_blocks_per_seq + lb];
                float weight = scores[t] / denominator;
                for (int d = 0; d < p.head_size; ++d) {
                    size_t vi = kv_index(block_id, off, kvh, d,
                                         p.block_size, p.num_kv_heads, p.head_size);
                    out[d] += weight * v_cache[vi];
                }
            }
        }
    }
}

测试时故意让 Block Table 非连续，例如 [7, 2, 11]，否则连续页表会让错误实现也得到正确结果。

三、DX12 Compute Shader 原型¶

1. Resource Binding¶

t0: StructuredBuffer<float> Q
t1: StructuredBuffer<float> KCache
t2: StructuredBuffer<float> VCache
t3: StructuredBuffer<int>   BlockTable
t4: StructuredBuffer<int>   ContextLens
u0: RWStructuredBuffer<float> Output
b0: PagedAttentionConstants

教学版使用 FP32 Buffer 简化 HLSL 读写。正确后再改为打包 FP16，并确认硬件支持、Load 粒度和转换成本。

2. HLSL 基线¶

一个 Thread Group 处理一个 (batch, q_head)，Group 内线程协作完成 Head Dim 与 Context 归约：

cbuffer Params : register(b0)
{
    uint BatchSize;
    uint NumQHeads;
    uint NumKVHeads;
    uint HeadSize;
    uint BlockSize;
    uint MaxBlocksPerSeq;
    float Scale;
    uint Padding;
};

StructuredBuffer<float> Q           : register(t0);
StructuredBuffer<float> KCache      : register(t1);
StructuredBuffer<float> VCache      : register(t2);
StructuredBuffer<int> BlockTable    : register(t3);
StructuredBuffer<int> ContextLens   : register(t4);
RWStructuredBuffer<float> Output    : register(u0);

groupshared float Scores[4096];       // 仅用于固定上限的教学版本
groupshared float Reduction[256];

uint KVIndex(uint blockId, uint offset, uint kvHead, uint d)
{
    return (((blockId * BlockSize + offset) * NumKVHeads + kvHead)
            * HeadSize + d);
}

[numthreads(256, 1, 1)]
void CSMain(uint3 groupId : SV_GroupID, uint lane : SV_GroupThreadID)
{
    uint b = groupId.y;
    uint qh = groupId.x;
    uint kvh = qh / (NumQHeads / NumKVHeads);
    uint contextLen = ContextLens[b];

    for (uint t = lane; t < contextLen; t += 256) {
        uint logicalBlock = t / BlockSize;
        uint offset = t % BlockSize;
        uint blockId = BlockTable[b * MaxBlocksPerSeq + logicalBlock];
        float dot = 0.0f;
        for (uint d = 0; d < HeadSize; ++d) {
            uint qi = (b * NumQHeads + qh) * HeadSize + d;
            dot += Q[qi] * KCache[KVIndex(blockId, offset, kvh, d)];
        }
        Scores[t] = dot * Scale;
    }
    GroupMemoryBarrierWithGroupSync();

    // reduceMax、exp/reduceSum 和 PV 在辅助函数中实现。
    float rowMax = ReduceMax(Scores, contextLen, lane);
    GroupMemoryBarrierWithGroupSync();
    float denominator = ExpAndReduceSum(Scores, contextLen, rowMax, lane);
    GroupMemoryBarrierWithGroupSync();
    AccumulatePV(b, qh, kvh, contextLen, denominator, lane);
}

groupshared Scores[4096] 只是正确性原型，会限制 Context Length 并占用较多 Shared Memory。优化版应采用第 11.2 节的 Online Softmax 分块流式处理，避免完整 Score Buffer。

3. DX12 资源状态与同步¶

每轮需要保证：

上传 BlockTable/ContextLens
  → COPY_DEST
  → UAV/SRV 可读状态
  → Dispatch
  → UAV Barrier（若后续 Pass 读取 Output）

若 Block Table 和 Context Lens 每步更新，使用持久映射 Upload Ring Buffer 或预分配 Upload Heap，避免逐步创建 Resource。Fence 保护 Ring Segment 在 GPU 完成前不被 CPU 覆盖。

4. Dispatch¶

commandList->SetPipelineState(pagedAttentionPSO.Get());
commandList->SetComputeRootSignature(rootSignature.Get());
commandList->SetComputeRootDescriptorTable(...);
commandList->Dispatch(numQHeads, batchSize, 1);

PSO、Root Signature 和 Descriptor Heap 应在初始化阶段创建。逐 Token 重建 PSO 或 Descriptor Heap 会让 CPU 开销淹没教学 Kernel 的收益。

四、TensorRT Plugin 后端¶

TensorRT 不执行 HLSL。Plugin 的 enqueue() 接收 CUDA Tensor 地址，并启动 CUDA/Triton Kernel。现代 TensorRT 版本的 Plugin 接口会演进，实际代码应以目标 TensorRT SDK 的头文件和示例为准。

1. Plugin 输入输出¶

建议把运行时变化值作为 Tensor 输入：

inputs[0] Q             FP16 [B, Hq, D]
inputs[1] KCache        FP16 [NB, BS, Hkv, D]
inputs[2] VCache        FP16 [NB, BS, Hkv, D]
inputs[3] BlockTable    INT32 [B, MaxBlocks]
inputs[4] ContextLens   INT32 [B]
output[0] O             FP16 [B, Hq, D]

block_size、num_heads、head_size 等模型不变量可序列化进 Plugin Field；Batch Size 和 Context Length 必须保持运行时动态。

2. Plugin 骨架¶

class PagedAttentionPlugin final : public nvinfer1::IPluginV2DynamicExt {
public:
    int enqueue(
        const nvinfer1::PluginTensorDesc* inputDesc,
        const nvinfer1::PluginTensorDesc* outputDesc,
        const void* const* inputs,
        void* const* outputs,
        void* workspace,
        cudaStream_t stream) noexcept override
    {
        Params p = makeParams(inputDesc);
        if (!validateRuntimeParams(p))
            return 1;

        launchPagedAttention(
            static_cast<const half*>(inputs[0]),
            static_cast<const half*>(inputs[1]),
            static_cast<const half*>(inputs[2]),
            static_cast<const int32_t*>(inputs[3]),
            static_cast<const int32_t*>(inputs[4]),
            static_cast<half*>(outputs[0]),
            p, stream);
        return cudaPeekAtLastError() == cudaSuccess ? 0 : 1;
    }
};

enqueue() 中不能隐式使用默认 Stream，不能执行同步 cudaMemcpy，也不应反复 cudaMalloc/cudaFree。临时空间使用 TensorRT 提供的 workspace 或初始化阶段持久分配。

3. Shape 与 Format 校验¶

supportsFormatCombination() 应明确允许的组合，getOutputDimensions() 返回 [B,Hq,D]，configurePlugin() 检查静态不变量。不要等到 Kernel 内部才发现 Hq % Hkv != 0。

4. TensorRT Network 接入¶

auto* pluginLayer = network->addPluginV2(inputs, 5, plugin);
auto* output = pluginLayer->getOutput(0);

若 KV Cache 需要跨多次 enqueueV3() 保持，最好由 Runtime Session 管理其 Device Buffer，并作为显式 Binding 传入。把可变请求状态藏在 Plugin 对象内部会破坏并发 Session、序列化和生命周期管理。

五、Runtime 侧 Block Manager¶

class KvBlockPool {
public:
    explicit KvBlockPool(uint32_t numBlocks)
        : refCount_(numBlocks, 0) {
        for (uint32_t i = 0; i < numBlocks; ++i)
            free_.push_back(i);
    }

    uint32_t allocate() {
        if (free_.empty()) throw std::runtime_error("KV pool exhausted");
        uint32_t id = free_.front();
        free_.pop_front();
        refCount_[id] = 1;
        return id;
    }

    void retain(uint32_t id) { ++refCount_.at(id); }

    void release(uint32_t id) {
        auto& count = refCount_.at(id);
        if (count == 0) throw std::logic_error("double release");
        if (--count == 0) free_.push_back(id);
    }

private:
    std::deque<uint32_t> free_;
    std::vector<uint32_t> refCount_;
};

Request 保存逻辑 Block Table；Pool 只管理物理页和引用。不要让 Shader/Plugin 自行决定请求应获得哪个 Block，它缺少全局调度和其他请求的生命周期信息。

六、混合长度 Decode Batch¶

不同请求拥有不同 ContextLens 和 Block Table，但 Q Shape 可以统一为 [B,Hq,D]。无需把 KV 聚合复制成一个新的连续 Buffer；PagedAttention 的价值正是直接通过页表读取原物理页。

Padding 只用于元数据 Shape 或 CUDA Graph Bucket，不应复制完整 KV：

request A: len=65, blocks=[7,2]
request B: len=17, blocks=[9]

BlockTable padded:
[7, 2]
[9,-1]

ContextLens:
[65,17]

Kernel 必须只读取 token_pos < context_len 的逻辑页，不能访问 Padding 的 -1。

七、正确性验证¶

分四层对齐：

  1. CPU 连续 KV Reference 与 CPU Paged Reference；
  2. CPU Paged Reference 与 DX12 输出；
  3. CPU Paged Reference 与 TensorRT Plugin 输出；
  4. 多步 Decode：每步写入新 KV 后再次计算。

测试矩阵：

维度 样例
Batch 1、2、7
Hq:Hkv 1:1、8:1、16:2
Head Size 64、128
Block Size 16、64、256
Context Length 1、B-1、B、B+1、上限
Block Table 连续、乱序、共享前缀

DX12 使用 PIX/GPU Validation，CUDA 使用 Compute Sanitizer：

compute-sanitizer --tool memcheck ./paged_attention_test
compute-sanitizer --tool racecheck ./paged_attention_test

Racecheck 对所有自定义访问模式并非都能给出完整结论，仍需边界测试和代码审查。

八、性能验收与结论边界¶

分别测量：

  • Kernel GPU 时间；
  • 每 Token 的 Block Table/ContextLens H2D 时间；
  • Runtime 组 Batch 的 CPU 时间；
  • Decode Step 端到端时间；
  • 连续 KV 基线与 Paged KV 的差异；
  • 不同碎片率和 Context Length 分布。

TPOT 12.85 ms → 6.50 ms 只有在基线包含的复制、分配或低效 Kernel 被明确记录时才有解释力。PagedAttention 本身增加间接寻址，它的主要系统收益是降低碎片、避免 KV 聚合复制并支持动态批处理；某个 Kernel 是否变快取决于基线和实现。
