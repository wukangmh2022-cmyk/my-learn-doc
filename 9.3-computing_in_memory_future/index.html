9.3 存算一体（Computing-in-Memory）的未来¶

概述¶

存算一体（Computing-in-Memory, CIM）把部分计算下沉到存储阵列或其附近，以减少数据在远端存储与计算单元之间的搬运。实现介质包括 SRAM、DRAM、NOR Flash、ReRAM/PCM 等，既有模拟方案也有数字方案。

CIM 缩短某些权重搬运路径，但输入/输出传输、片间通信、ADC/DAC、数字后处理和控制仍然存在。瓶颈可能转移，而不是简单从“通信”反转为“计算”。

工作原理：NOR Flash 模拟计算¶

物理基础¶

以电阻式模拟阵列为例，权重编码为单元电导，输入编码为电压，列电流依据欧姆定律与基尔霍夫定律累加。器件编程、差分编码、ADC/DAC 和校准使实际系统远比理想公式复杂。

权重以电导值（G）的形式存储在 Flash 单元中
输入以电压值（V）的形式施加在位线上
输出电流（I = G × V）在列线上自然累加

I_out_j = Σ_i (G_ij × V_in_i)

这个公式，就是 向量-矩阵乘法（VMM）——正是神经网络中最核心的操作。

与传统 GPU 的对比¶

特性 传统 GPU / 冯诺依曼架构 NOR Flash 存算一体
核心瓶颈 随工作负载变化：计算、内存或互联 阵列利用率、转换器、噪声、数据搬运与数字后处理
主要优势 通用性、成熟工具链与高精度 对适配的矩阵/向量操作可减少权重搬运并提高能效
精度 支持多种整数与浮点路径 模拟方案常受噪声和器件波动限制；数字 CIM 约束不同
应用场景 云端训练/推理 端侧极低功耗场景
技术成熟度 高度成熟 从研究原型到商用产品均有，成熟度依介质和场景差异很大

现状：能做什么？不能做什么？¶

已能做的：矩阵乘（MatMul）¶

存算一体的主战场是矩阵乘法——这正是它天生的能力。目前产业界的核心应用集中在 AI 推理的矩阵乘上：

  • 论文与产品常报告很高的阵列级或芯片级 TOPS/W，但口径可能是否包含 ADC/DAC、稀疏性、利用率和外部存储，不能直接横向比较。
  • 商用落地主要集中在功耗敏感、模型与算子范围受控的端侧场景；产品状态和部署规模属于时效性信息，应引用厂商或第三方资料并标注日期。

研究进展中的：非线性算子¶

对于 MatMul 以外的操作，学术界和工业界使用三种思路：

思路一：在模拟域里"硬计算"

用专用的 CMOS 模拟电路直接完成非线性计算，避免频繁的数模转换：

  • ReLU：已能支持，通过查找表或可重构电路实现
  • 激活函数（SiLU、GELU）：利用泰勒展开或分段拟合，在纯模拟域高效计算
  • 通用逻辑：利用 NOR Flash 多阈值电压特性，可配置出 AND、OR、XOR 等 16 种完备布尔逻辑

思路二：软硬件协同的"编译器魔法"

只让存算硬件做最擅长的事（大矩阵乘），其他活交给旁边数字核心：

Compiler 分析计算图：
┌─ MatMul/Conv     → 映射到存算阵列（模拟计算，高能效）
├─ ReLU/Add        → 可融合进存算阵列或由数字核心处理
├─ Softmax/LayerNorm → 交给 RISC-V/DSP 核心（数字计算）
└─ 控制流/复杂逻辑  → 交给通用处理器

思路三：架构层面的异构集成

三维堆叠异构：不同芯片层用不同工艺制造——SRAM 阵列做高速缓存，RRAM 阵列做非易失存储和矩阵计算。

当前还做不到的¶

限制 原因
高精度训练（FP32/FP64） 模拟电路受工艺波动和噪声影响，精度有限
复杂控制流 分支、循环、动态调度需要通用 ALU
软件生态兼容 无 CUDA 级别的工具链，需要专用编译器
ADC/DAC 与外围电路 可能占据显著能耗和面积，比例取决于架构、精度和测量口径

为什么存算一体如此重要¶

它打破了"内存墙"¶

在许多数据密集型工作负载中，存储层次的数据移动能耗可能高于算术本身，但占比依芯片、存储层级和工作负载而变。内存墙指带宽/延迟增长跟不上计算需求，不应绑定到固定的 90%。

存算一体的核心贡献在于减少某些长距离数据搬运。阵列内部、输入输出、转换器和系统互联的数据流仍不可避免。

这也是为什么存算一体芯片能以极低功耗完成 AI 推理的核心原因。

它重新分配系统瓶颈¶

理想阵列把乘加与权重读取结合，但系统级流水线仍需在阵列、转换器、数字核心和片外内存之间协调：

传统加速器：  计算单元 <-> 分层存储，优化复用与带宽
CIM 系统：    存内阵列 <-> ADC/DAC <-> 数字后处理 <-> 系统内存
共同目标：    减少总能耗与端到端延迟，而不是假设某类通信为零

产业状态需要带日期和来源¶

该领域同时存在论文原型、IP、端侧芯片和系统产品。诸如“首款”“百万部署”“支持某参数规模”的说法高度依赖定义与发布时间，知识手册应为每条结论附原始来源和访问日期；没有来源时不宜作为稳定知识保留。

未来展望：一个异构的世界¶

存算一体不太可能完全取代 GPU，更可能扮演一个"最强辅助"的角色：

未来推理系统架构：

┌─────────────────────────────────────┐
│          CPU（逻辑控制大脑）          │
│     LayerNorm, Softmax, 控制流       │
└────────────┬─────────────────────────┘
             │
┌────────────▼─────────────────────────┐
│     存算一体阵列（算力心脏）          │
│     MatMul, Conv, Attention 核心      │
│     模拟计算，能效极高               │
└─────────────────────────────────────┘

它的角色是：

  1. 补充矩阵计算路径——是否替代现有 Tensor Core 取决于精度、可编程性和数据流
  2. 专注于大规模矩阵乘——天生擅长的操作
  3. 和通用核心协同——复杂操作交给 CPU/DSP
  4. 从端侧走向云端——现阶段在耳机/摄像头，未来可能在数据中心

正如一位业内专家所指出的：存算一体要对抗的并不是某款芯片，而是整个 NVIDIA CUDA 生态。这是一个软件生态的战争，而不仅仅是硬件的竞赛。

关键结论¶

  1. 物理原理：部分模拟阵列利用电导与电流累加完成向量-矩阵乘法，能减少权重搬运但通信开销不为零
  2. 主战场是矩阵乘：当前产业界核心应用在 AI 推理的 MatMul，效率远超传统架构
  3. 非线性计算正在突破：ReLU 已支持，更复杂的算子通过三种思路（模拟域硬算、编译器调度、异构集成）逐步解决
  4. 精度和生态是硬伤：模拟精度有限（INT8 为主），且缺乏成熟的工具链和编程模型
  5. 前景广阔但角色明确：存算一体不会完全取代 GPU，但会在特定场景（端侧、低功耗）成为不可替代的选项

更稳妥的结论：CIM 通过改变数据驻留位置减少特定搬运成本，同时引入转换、精度、映射、耐久性和工具链等新约束。

延伸：从架构视角看存算一体¶

将存算一体放在计算架构的光谱中看：

纯冯诺依曼 ←───────────── 纯存算一体
  │                           │
  GPU/CUDA                    NOR Flash CIM
  ├─ 通信是瓶颈                ├─ 计算是瓶颈
  ├─ 数据搬运成本可能很高       ├─ 减少部分长距离搬运
  ├─ 精度高/生态成熟           ├─ 精度有限/生态起步
  └─ 通用性强                  └─ 专精矩阵乘

未来的趋势不是二选一，而是融合——在通用 GPU 中集成更多的存内计算单元，让同一块芯片能根据不同任务类型，在"通信敏感"和"计算敏感"模式之间动态切换。
