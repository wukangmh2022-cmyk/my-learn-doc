6.4 FlashAttention: Online Softmax + Tiling 的经典案例

概述

FlashAttention 是算子融合（Operator Fusion）和分块计算（Tiling）思想在 Attention 上的极致应用。它本质上就是把一个 TBDR (Tile-Based Deferred Rendering) 渲染器写成了 CUDA Kernel。

如果你搞过移动端 GPU 的 TBDR 优化，读到 FlashAttention 的论文时会发现——公式不用看，光看图就能猜出数据流向。

Attention 的标准实现：带宽灾难

标准 Attention 的计算公式：

O = Softmax(Q * K^T) * V

其中 Q、K、V 的形状都是 [N, d]（N 为序列长度，d 为 Head Dim）。

标准实现的问题

Step 1: S = Q @ K^T        → 结果 S 形状 [N, N]，写入 HBM
Step 2: P = Softmax(S)     → 从 HBM 读 S，算 Softmax，写回 HBM
Step 3: O = P @ V          → 从 HBM 读 P 和 V，算结果

中间矩阵 S (N × N) 被完整写入 HBM 再读出来，总显存读写量是 O(N² + N d)。当 N 是 4K、8K、甚至 128K 时，这个中间结果的带宽开销占据了压倒性的主导地位。

这就像你在渲染时，把 GBuffer（深度、法线、颜色）全部写回显存，下个 Pass 再读出来——你肯定知道这有多浪费。

FlashAttention 的解决思路：TBDR 的完美映射

你当时在聊天中精准地指出：

"FlashAttention 类似于 TBDR (Tile-Based Deferred Rendering)"

这个类比完全正确，而且比"Tiled Deferred Shading"更贴切：

层级 TBDR（移动端 GPU 渲染） FlashAttention（AI 推理）
分块策略 把屏幕分成若干 Tile（如 32x32 像素） 把注意力矩阵分成若干 Block（如 128x128）
片上内存 Tile Buffer（片上 SRAM，极快） Shared Memory（SM 内的 SRAM）
避免的操作 避免反复读写 Frame Buffer 避免反复读写 HBM（中间矩阵 Q × K^T）
核心收益 减少带宽占用，省电 减少带宽占用，加速

关键对应关系

  1. Tile Buffer ≈ Shared Memory：两者都是容量有限（128KB 级别）但速度极快的片上内存。数据分块加载进去，在片上完成所有计算后只写回最终结果。

  2. 解决 Overdraw ≈ Online Softmax 重计算：TBDR 通过 Early-Z 和 Tile 内排序来解决 Overdraw（同一像素被多次写入）；FlashAttention 通过Online Softmax——不存完整的 S 矩阵，而是每次加载一个新的 K/V Block 时，重新读取之前算过的部分统计量（m 和 l）并更新——本质上就是在用重计算换带宽。

  3. 分块加载所有光源 ≈ 分块加载所有 K/V Block：TBDR 中每个 Tile 加载该 Tile 覆盖的所有光源列表；FlashAttention 中每个 Q Block 循环加载所有 K/V Block，在片上计算部分 Softmax 再累加结果。

Online Softmax：核心创新

Online Softmax 是整个 FlashAttention 的灵魂。它允许你不存储完整的 S 矩阵，而是一边加载 K/V Block，一边逐步更新 softmax 结果。

标准 Softmax

输入向量 x (长度 N)
m = max(x[i])          → 找最大值
s = sum(exp(x[i] - m))  → 计算分母
p[i] = exp(x[i] - m) / s → 输出概率

问题：你需要知道所有 N 个 x[i] 才能算 Softmax——这意味着你必须先把完整的 Q×K^T 算出来。

Online Softmax（逐步更新）

初始化: m_prev = -inf, l_prev = 0, o_prev = 0

对每个 K/V Block:
    1. 计算当前 Block 的 S_block = Q @ K_block^T    [N, BLOCK_SIZE]
    2. m_curr = max(m_prev, row_max(S_block))
    3. l_curr = exp(m_prev - m_curr) * l_prev + sum(exp(S_block - m_curr))
    4. o_curr = exp(m_prev - m_curr) * o_prev + exp(S_block - m_curr) @ V_block
    5. 更新状态，进入下一 Block

这个过程不需要把完整的 S 写回 HBM——S_block 在 Shared Memory 中算完即丢弃。你只需要维护三个统计量（m, l, o），它们从 Block 到 Block 渐近地收敛到全局 Softmax 的结果。

CUDA 与 DX12 Compute Shader 对照

CUDA 代码骨架：分块 Attention

// CUDA FlashAttention Forward Pass (简化版)
// 假设一个 Block 处理一个 Q Tile: Q_tile [B_r, d], K_tile [B_c, d], V_tile [B_c, d]
#define B_r 32   // Q 分块大小 (Tile Size)
#define B_c 64   // K/V 分块大小 (Block Size)
#define d   128  // Head Dim

__global__ void flash_attention_kernel(float* Q, float* K, float* V, float* O,
                                        int N, int d) {
    __shared__ float Q_s[B_r][d];
    __shared__ float K_s[B_c][d];
    __shared__ float V_s[B_c][d];
    __shared__ float S_s[B_r][B_c]; // 中间结果: Q_s * K_s^T

    int tx = threadIdx.x, ty = threadIdx.y;
    int row = blockIdx.x * B_r + tx; // Q 的行索引

    // 加载 Q Tile 到 Shared Memory
    if (row < N && ty < d) {
        Q_s[tx][ty] = Q[row * d + ty];
    }
    __syncthreads();

    // Online Softmax 状态
    float m_prev = -INFINITY;
    float l_prev = 0.0f;
    float o_prev[d] = {0.0f}; // 寄存器中维护输出累加

    // 循环所有 K/V Block
    for (int block_start = 0; block_start < N; block_start += B_c) {
        // 加载 K_s 和 V_s
        if (tx < B_c && ty < d && (block_start + tx) < N) {
            K_s[tx][ty] = K[(block_start + tx) * d + ty];
            V_s[tx][ty] = V[(block_start + tx) * d + ty];
        }
        __syncthreads();

        // 计算 S_s = Q_s @ K_s^T  (每个线程外循环 N 元素)
        // ... (矩阵乘，结果在 Shared Memory 或寄存器中)

        // 更新 Online Softmax
        float m_curr = m_prev;
        float l_curr = l_prev;
        // 1. 找当前 Block 的行最大值
        // 2. 更新 m_curr = max(m_prev, m_block)
        // 3. 更新 l_curr = exp(m_prev - m_curr) * l_prev + sum(exp(S - m_curr))
        // 4. 更新 o_curr = exp(m_prev - m_curr) * o_prev + exp(S - m_curr) @ V_block

        m_prev = m_curr;
        l_prev = l_curr;
        // o_prev 在寄存器中持续更新
        __syncthreads();
    }

    // 最终输出: O[row] = o_prev / l_prev
    if (row < N) {
        for (int k = 0; k < d; k++) {
            O[row * d + k] = o_prev[k] / l_prev;
        }
    }
}

DX12 Compute Shader 代码骨架

下面是你在之前对话中看到的 DX12 + HLSL 实现 FlashAttention 的核心骨架：

// AttentionKernel.hlsl
// FlashAttention 的 DX12 Compute Shader 实现 (简化版)

#define TILE 32         // 分块大小
#define D_HEAD 128      // Head Dim

RWStructuredBuffer<float> Output : register(u0);
StructuredBuffer<float> Q : register(t0);
StructuredBuffer<float> K : register(t1);
StructuredBuffer<float> V : register(t2);

// groupshared memory = 图形工程师眼中的 Tile Buffer
groupshared float sharedQ[TILE][D_HEAD];
groupshared float sharedK[TILE][D_HEAD];

[numthreads(TILE, TILE, 1)]
void main(uint3 DTid : SV_DispatchThreadID, 
          uint3 GTid : SV_GroupThreadID, 
          uint3 Gid : SV_GroupID)
{
    uint row = DTid.x;  // SeqIdx
    uint col = DTid.y;  // DimIdx
    uint seqLen = 1024; // 从常量传入

    // 1. 加载 Q 和 K 的分块到 groupshared (Tile Buffer)
    if (row < TILE && col < D_HEAD) {
        sharedQ[row][col] = Q[row * D_HEAD + col];
        sharedK[row][col] = K[row * D_HEAD + col];
    }
    GroupMemoryBarrierWithGroupSync();

    // 2. 计算当前 Tile 的 Attention Score (Q * K^T)
    if (row < TILE && col < TILE) {
        float acc = 0.0f;
        for (int d = 0; d < D_HEAD; d++) {
            acc += sharedQ[row][d] * sharedK[col][d];
        }
        // acc = Q[row] 和 K[col] 的点积

        // 3. 这里应该是 Online Softmax + 乘以 V
        //    真实 FlashAttention 需要循环所有 K/V Block
        Output[row * TILE + col] = acc;
    }
}

注意：上面的 HLSL 代码只展示了单个 Tile 的 Q*K^T 计算。完整的 FlashAttention 需要：

  • 外层循环：对每个 Q Block，循环遍历所有 K/V Block。
  • Online Softmax 状态更新：跨 Block 维护 m（最大值）和 l（归一化分母），在寄存器中更新。
  • 最终融合：将乘 V 的累加（o）也融合在循环内。

C++ DX12 应用骨架

// main.cpp — DX12 设备初始化 + 资源管理 + 调度
int main() {
    // 1. 创建设备和 Command Queue
    ID3D12Device* pDevice;
    ID3D12CommandQueue* pQueue;
    ID3D12GraphicsCommandList* pCmdList;
    InitDX12(&pDevice, &pQueue, &pCmdList);

    // 2. 创建根签名 (Root Signature)
    ID3D12RootSignature* pRootSig;
    CreateRootSignature(pDevice, &pRootSig);

    // 3. 定义张量 Shape: B=1, H=12, SeqLen=1024, D=128
    const UINT B = 1, H = 12, S = 1024, D = 128;
    UINT64 tensorSize = B * H * S * D * sizeof(float);

    // 4. 在 GPU 上分配 Q, K, V 和 Output Buffer
    ComPtr<ID3D12Resource> pQ = CreateBuffer(pDevice, tensorSize, D3D12_HEAP_TYPE_DEFAULT);
    ComPtr<ID3D12Resource> pK = CreateBuffer(pDevice, tensorSize, D3D12_HEAP_TYPE_DEFAULT);
    ComPtr<ID3D12Resource> pV = CreateBuffer(pDevice, tensorSize, D3D12_HEAP_TYPE_DEFAULT);
    ComPtr<ID3D12Resource> pOut = CreateBuffer(pDevice, tensorSize, D3D12_HEAP_TYPE_DEFAULT);

    // 5. 录制 Command List
    pCmdList->SetComputeRootSignature(pRootSig);
    // 设置 Root Descriptor (传 GPU 虚拟地址)
    // pCmdList->SetComputeRootShaderResourceView(0, pQ->GetGPUVirtualAddress());
    // ...

    // 6. 调度: 每个 Thread Group 处理一个 Head 的一个 Block
    //    实际需要根据 SeqLen 计算 Dispatch 次数
    const UINT TILE = 32;
    UINT numGroupsX = (S + TILE - 1) / TILE;
    pCmdList->Dispatch(numGroupsX, numGroupsX, H); // X×Y = Block 网格, Z = Head

    // 7. Barrier + 执行
    pCmdList->Close();
    pQueue->ExecuteCommandLists(1, (ID3D12CommandList**)&pCmdList);

    // 8. 等待 Fence（同步 CPU-GPU）
    // 9. 读回 Output 验证
    return 0;
}

从 TBDR 视角重读 FlashAttention 论文

如果你带着 TBDR 的思维去读 FlashAttention 论文，你会发现以下一一对应：

FlashAttention 论文概念 TBDR 对应物
Tiling (分块) 屏幕分 Tile (32x32)
SRAM / Shared Memory Tile Buffer (片上内存)
Online Softmax (重计算 + 逐步更新) 解决 Overdraw（不存中间结果，重新算）
Block Size 调优 Tile Size 调优（太大则片上放不下）
Bank Conflict 规避 Shared Memory 踩踏（同样需要 Padding）
减少 HBM 事务 减少 Global Memory 事务（提高 Tile Buffer 命中率）

落地的关键教训

这些经验你在写 TBDR Shader 时已经付出了血的代价，现在直接迁移到 FlashAttention：

  1. Tile Size 不能太大：片上放不下（Shared Memory 只有几十 KB），Block Size 需要调优。
  2. 要避免 Bank Conflict：写 Triton/Kernel 时，你本能会做 Padding 来规避冲突。
  3. 重计算换带宽：不存中间结果，重新算 Softmax 归一化项——这就是 Online Softmax 的精髓。
  4. 循环展开：FlashAttention 的外层循环（遍历所有 K/V Block）建议手动展开或让编译器优化，减少循环开销。

总结

FlashAttention 是你熟悉的图形渲染技术在 AI 推理中最完美的映射。它的核心创新不在于发明了新的数学，而在于用你在 TBDR 中早已深知的工程策略——分块加载到片上内存、在线处理避免中间结果写回——来解决 AI 中的带宽瓶颈。

"FlashAttention 就是一个把 TBDR 渲染器写成 CUDA Kernel 的作品。你如果会写 TBDR 的 Shader，那就已经会了 FlashAttention 的核心思维。剩下的只是把 '像素' 换成 'Token'，把 'Tile Buffer' 换成 'Shared Memory'。"
