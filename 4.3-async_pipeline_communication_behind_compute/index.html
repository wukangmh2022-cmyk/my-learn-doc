4.3 异步流水线: Communication behind compute (双缓冲 / DMA 重叠)¶

概述¶

Communication behind compute（计算掩盖通信）是 GPU 优化中最核心的延迟掩盖技术。它的思想很简单：

不要等数据——让计算和搬运像流水线一样同时跑起来。

如果说\"算子融合\"是微观层面的优化（单个 Kernel 内合并操作），那么\"异步流水线\"就是宏观层面的优化（多个 Kernel / Stream 间的并发）。

核心思想：生产者-消费者速度不匹配¶

经典的流水线问题¶

串行（慢）：
  [加载 Tile 0] → [计算 Tile 0] → [加载 Tile 1] → [计算 Tile 1] → ...
  总时间 = sum(加载时间 + 计算时间)

流水线（快）：
  [加载 Tile 0]  →  [加载 Tile 1]  →  [加载 Tile 2]  → ...
                    [计算 Tile 0]  →  [计算 Tile 1]  → ...
  总时间 = max(sum(加载时间), sum(计算时间))

你的直觉：这就是你用三重缓冲做帧并行时的思想——CPU 在准备下一帧数据时，GPU 在渲染当前帧。同样的逻辑，只是搬到了微观的 Kernel 内部。

图形中你已经掌握的思想¶

图形渲染 AI 推理
CPU 准备第 N+1 帧数据 DMA 引擎加载第 N+1 个 Tile
GPU 渲染第 N 帧 SM 计算第 N 个 Tile
轮询 Fence 检查第 N 帧是否完成 cuda::memcpy_async + barrier 检查数据是否到位

异步数据搬运：cuda::memcpy_async¶

在 Compute Capability 8.0+ 上，满足地址空间、大小和对齐条件的 Global-to-Shared cuda::memcpy_async 可映射到硬件异步拷贝路径。它由 SM 的拷贝流水线执行，不应笼统描述成独立 DMA 引擎。

传统做法（同步加载）¶

__shared__ float tile_A[TILE_SIZE][TILE_SIZE];

// 每个线程负责加载一个元素
tile_A[ty][tx] = A[row * stride + col];  // 线程阻塞等待数据返回
__syncthreads();                          // 确保所有人都加载完
// 现在才能开始计算...

问题：加载数据时，SM 在空等——几百个 cycle 的访存延迟，SM 什么也没干。

异步做法（数据预取）¶

#include <cuda/barrier>

__shared__ float tile_A[TILE_SIZE][TILE_SIZE];
__shared__ float tile_B[TILE_SIZE][TILE_SIZE];

__shared__ cuda::barrier<cuda::thread_scope_block> block_barrier;
if (threadIdx.x == 0) {
    init(&block_barrier, blockDim.x);
}
__syncthreads();

// 发出异步拷贝指令（DMA 引擎在后台搬运）
cuda::memcpy_async(&tile_A[ty][tx], &global_A[idx], sizeof(float), block_barrier);
cuda::memcpy_async(&tile_B[ty][tx], &global_B[idx], sizeof(float), block_barrier);

// SM 可以立刻去做其他事！不需要等待数据返回
// 比如：初始化累加器、准备地址计算...

// 等到 barrier 同步，确保数据到位
block_barrier.arrive_and_wait();

// 现在数据已经在 Shared Memory 里了，开始计算
float sum = 0.0f;
for (int k = 0; k < TILE_SIZE; k++) {
    sum += tile_A[ty][k] * tile_B[k][tx];
}

用图形语言翻译¶

图形 (Compute Shader) CUDA（同步） CUDA（异步）
tex2D 自动采样 手动 tile[ty][tx] = global[idx] cuda::memcpy_async + barrier
纹理单元执行采样与过滤 线程执行 Load/Store SM 异步拷贝流水线处理符合条件的 Global-to-Shared 传输
隐式 Cache 显式 Shared Memory 显式 Shared Memory + 流水线预取

双缓冲（Double Buffering）：真正的流水线¶

异步拷贝常与多阶段缓冲配合，目标是让加载和计算重叠。是否完全覆盖取决于两阶段耗时、依赖和可用并行资源。

// 概念伪代码：省略 barrier 初始化、边界与 pipeline stage 管理。
__shared__ float tile_A_buf[2][TILE_SIZE][TILE_SIZE];
__shared__ float tile_B_buf[2][TILE_SIZE][TILE_SIZE];

auto barrier = cuda::barrier(cuda::thread_scope_block);

// 先加载第 0 块
cuda::memcpy_async(&tile_A_buf[0][ty][tx], &global_A[0 * TILE_SIZE], ..., barrier);
cuda::memcpy_async(&tile_B_buf[0][ty][tx], &global_B[0 * TILE_SIZE], ..., barrier);
barrier.arrive_and_wait();

for (int tile = 1; tile < num_tiles; tile++) {
    // 在后台异步加载下一块
    // 注意：这和下面的计算同时发生！
    cuda::memcpy_async(&tile_A_buf[tile % 2][ty][tx], &global_A[tile * TILE_SIZE], ..., barrier);
    cuda::memcpy_async(&tile_B_buf[tile % 2][ty][tx], &global_B[tile * TILE_SIZE], ..., barrier);

    // 计算当前已加载好的块
    compute(tile_A_buf[(tile - 1) % 2], tile_B_buf[(tile - 1) % 2]);

    // 等下一块加载完
    barrier.arrive_and_wait();
}

// 算最后一块
compute(tile_A_buf[(num_tiles - 1) % 2], tile_B_buf[(num_tiles - 1) % 2]);

Communication behind compute 的宏观版本¶

双 Stream：计算和通信分离¶

在更宏观的层面，你可以用两个 CUDA Stream 来重叠计算和通信：

cudaStream_t streamCompute, streamComm;
cudaStreamCreate(&streamCompute);
cudaStreamCreate(&streamComm);

// 在通信流里异步拷贝
cudaMemcpyAsync(dst, src, size, cudaMemcpyHostToDevice, streamComm);

// 在计算流里跑 Kernel（与拷贝同时进行）
kernel<<<grid, block, 0, streamCompute>>>(...);

// 计算流需要等通信流完成（用 Event 做依赖）
cudaEvent_t event;
cudaEventCreate(&event);
cudaEventRecord(event, streamComm);
cudaStreamWaitEvent(streamCompute, event);

结果：SM 在算 Kernel 的同时，PCIe 在后台搬运数据。总耗时 = max(传输时间, 计算时间)，而不是两者之和。

你的图形经验完美迁移¶

图形引擎（宏观） AI 推理引擎（微观）
CPU 准备第 N+1 帧的顶点数据 DMA 加载第 N+1 个 Tile 到 Shared Memory
GPU 渲染第 N 帧 SM 计算第 N 个 Tile
轮询 Fence → 查下一帧是否完成 barrier.arrive_and_wait() → 查数据是否到位
三重缓冲 → 3 个后备 Buffer 双缓冲 → 2 份 Shared Memory Buffer

Ring AllReduce 中的通信掩盖计算¶

在分布式训练中，Communication behind compute 的另一个经典案例是 Ring AllReduce：

常规 AllReduce（串行）：
  [计算梯度] → [等待通信] → [AllReduce] → [等待完成] → [继续计算]

异步 AllReduce（流水线）：
  [计算第 i 块梯度] → 同时 [通信第 i-1 块梯度] → 同时 [累加第 i-2 块梯度]

你的直觉：\"把自己部分的数据乘以权重传递到下一个节点，与此同时继续后面的计算\"——这完全正确，这就是 Ring AllReduce 的异步流水线本质。

总结：你的认知固化¶

不要把时间花在等数据上，而是让计算和搬运像流水线一样跑起来。
