1.2 GPU 硬件层级：SM、执行管线与图形固定功能单元¶

GPU 的顶层组成¶

从功能上看，现代 GPU 可以分为四组主要子系统：

  • 任务前端与分发系统：接收命令并把图形或计算任务分派到后续单元。
  • 可编程处理器阵列：由多个 SM（其他厂商可能称 Compute Unit 等）组成，执行 Shader 或计算 Kernel。
  • 存储系统：包括片上缓存、L2、内存控制器以及 HBM/GDDR。
  • 固定功能单元：实现光栅化、纹理采样、颜色混合等特定图形操作；不同产品可能裁剪其中一部分。

这些子系统处于不同的组织层级。SM 是可编程处理器集群；Texture Unit 是供 Shader 使用的专用采样路径；ROP 则属于图形输出后端。

硬件层级图¶

flowchart TB
    GPU["GPU Device"] --> FE["Front End / Work Distributor"]
    GPU --> ARRAY["可编程处理器阵列"]
    GPU --> FIXED["图形固定功能管线（具体型号可省略部分单元）"]
    GPU --> MEM["Memory System"]

    ARRAY --> SM["SM / Compute Unit"]
    SM --> SCHED["Warp/Wave Scheduler + Dispatch"]
    SM --> RF["Register File"]
    SM --> EXEC["FP/INT/SFU/Load-Store 执行管线"]
    SM --> TC["Tensor/MMA 执行管线（支持时）"]
    SM --> SRAM["Shared Memory / L1"]

    FIXED --> RASTER["Geometry / Rasterizer"]
    FIXED --> TEX["Texture Addressing & Filtering"]
    FIXED --> ROP["ROP: Blend / Depth / Stencil / RT Write"]

    MEM --> L2["L2 Cache"]
    MEM --> VRAM["HBM / GDDR"]
    MEM --> MMU["MMU / Memory Controllers"]

这是一张概念图，不代表所有模块都有一条独占物理连线。不同厂商、代际和 SKU 会重新组织或省略单元。例如数据中心计算 GPU 可能保留 SM/Tensor Core 和内存系统，但不提供完整的光栅化、ROP 或显示管线。

可编程执行：SM 与线程执行¶

SM 是理解 GPU 可编程执行模型的中心：它决定 Kernel 的线程块如何驻留、Warp 如何调度以及指令如何使用执行资源。

SM 负责什么¶

  1. 接收一个或多个 Thread Block / Workgroup。
  2. 把线程组织为 Warp（NVIDIA 通常为 32 线程）并选择可运行 Warp。
  3. 向不同执行管线发射指令。
  4. 为驻留线程分配寄存器和 Shared Memory。
  5. 用其他 Warp 的工作隐藏指令或访存延迟。

SM 的主要资源¶

层级 作用 直接影响的问题
Warp Scheduler / Dispatch 选择 Warp 并发射指令 延迟隐藏、分支分歧、指令吞吐
Register File 保存线程私有状态 寄存器压力、Spill、Occupancy
FP/INT/SFU 管线 执行通用算术和特殊函数 指令吞吐、依赖链、ILP
Load/Store 管线 生成和执行内存访问 合并访问、延迟、带宽
Shared Memory / L1 Block 内显式复用与自动缓存 Tiling、Bank Conflict、容量
Tensor/MMA 管线 执行特定形状的矩阵乘加 数据类型、布局、Tile 与吞吐

“CUDA Core”通常指某类标量算术执行通道，而不是能独立调度线程的“小 CPU”。Kernel 由 Warp 调度器发射到合适的执行管线；不能只用“CUDA Core 数量 × 频率”准确预测实际性能。

存储系统¶

Register、Shared Memory/L1、L2 与 HBM/GDDR 共同构成由近到远的存储层次。分析 CUDA Kernel 时，需要确定：

  • 数据从哪一层读取？
  • 同一数据会在哪个范围内复用：Thread、Warp、Block 还是多个 SM？
  • 访问能否合并，是否发生 Bank Conflict？
  • 寄存器与 Shared Memory 用量会让多少 Block 同时驻留？

详细内容见第 1.3 和第 5.2 节。

图形固定功能路径¶

图形渲染除了使用 SM 执行 Vertex、Pixel 和 Compute Shader，还会经过几何处理、光栅化、纹理采样以及输出合并等专用路径。Texture Unit 和 ROP 应在这条流水线中理解。

Texture Unit / TMU¶

Texture Unit 是 Shader 使用的专用采样路径，常见职责包括：

  • 地址模式与 LOD 处理；
  • 双线性、三线性和各向异性过滤；
  • 部分纹理格式的解码与采样；
  • 配合 Texture Cache 改善二维空间访问。

CUDA 可以通过 Texture Object 使用纹理采样与缓存语义。GEMM 和 Attention 等计算通常使用普通 Global Load、Cache、Shared Memory 和寄存器，因为它们主要需要矩阵 Tile 复用，而不是纹理过滤。

问题 Texture Path Shared Memory
管理方式 硬件缓存与采样语义 程序显式读写的 Block Scratchpad
擅长任务 空间采样、过滤、地址模式、特定格式 已知的 Block 内复用、转置、Swizzle、归约
是否互斥 否 否；同一程序可同时使用

ROP¶

ROP 位于图形输出合并阶段，典型工作包括：

  • 深度与模板测试的相关后端操作；
  • 颜色混合和写掩码；
  • 多重采样相关的存储/解析路径；
  • 向 Render Target 写回结果。

ROP 执行图形 API 定义的固定 Blend、Depth 和 Stencil 语义。它与可编程内存模型中的原子读改写指令属于不同机制，也不参与一般的矩阵乘或 Elementwise Kernel。ROP 的吞吐主要影响填充率、颜色混合和 MSAA 等图形工作负载。

图形与 AI 工作负载的硬件关系¶

图形 Shader 和 CUDA Kernel 都依赖可编程执行资源与存储层次，但具体 GPU SKU 未必同时拥有完整图形和计算能力。

层面 图形工作负载 AI/CUDA 工作负载
可编程执行 Vertex/Pixel/Compute Shader 使用执行管线 CUDA Kernel 使用 FP/INT/Load-Store/Tensor 管线
片上存储 Register、Cache、groupshared Register、Cache、__shared__
专用单元 Rasterizer、Texture Unit、ROP、可选 RT Core Tensor/MMA 管线，以及型号支持的异步拷贝等路径
常见瓶颈 几何、Shader、采样、填充率或带宽 计算、HBM、延迟、通信或 Launch 开销

建议学习顺序¶

优先级 应掌握内容 原因
1 Thread / Block / Warp / SM 决定工作如何映射和调度
2 Register / Shared / L1 / L2 / HBM 决定数据移动和复用成本
3 CUDA Core、Tensor Core、Load/Store 管线 决定不同指令走哪类执行资源
4 Occupancy、分歧、合并访问、Bank Conflict 连接代码与性能
5 Rasterizer、TMU、ROP 图形方向必学；纯 CUDA/AI 只需建立边界

这一路径先建立任务映射、可编程执行和数据移动的主干，再按学习方向补充图形固定功能单元，能够避免混淆设备、处理器集群、执行管线和流水线阶段。
