1.2 渲染管线与硬件单元 (SM, TMU, ROP)

概述

GPU 的渲染管线由多个专用硬件单元组成，每个单元负责管线中的一个特定阶段。理解这些硬件单元，是打通图形渲染与 AI 计算底层认知的关键一步。

本质上，AI 推理和图形渲染跑在完全相同的硬件上——只是不同的硬件单元被不同的 workload 所利用。

核心硬件单元概览

硬件单元 全称 负责阶段 图形中的角色 AI 计算中的角色
SM Streaming Multiprocessor 着色器执行 运行 Pixel/Vertex/Compute Shader 运行 CUDA Kernel（所有通用计算）
TMU Texture Mapping Unit 纹理采样 执行 tex2D 采样，硬件插值滤波 没有直接对应（AI 手动用 Shared Memory 加载替代）
ROP Render Output Unit 像素输出 颜色混合、深度测试、MSAA 解析 可类比原子操作单元（atomicAdd）

SM（流式多处理器）—— GPU 的计算核心

图形中的 SM

SM 是 GPU 上执行 Shader 指令的硬件单元。一个 GPU 包含几十到上百个 SM（如 A100 有 108 个 SM）。

每个 SM 内部包含： - CUDA Core：标量 ALU，执行浮点/整数运算 - Tensor Core：专用矩阵乘加单元（从 Volta 架构开始引入） - Shared Memory：片上 SRAM，软件显式管理 - L1 Cache：片上 SRAM，硬件自动管理 - Register File：最大带宽的存储，线程私有 - Warp Scheduler：每个 SM 有 4 个 Warp Scheduler，每个负责 2 个 Warp

你的渲染视角：SM 就是 GPU 上的"计算农场"。你写的每一个 [numthreads(8,8,1)] 的 Compute Shader，最终都是被分发到这些 SM 上执行。SM 的数量 × 每个 SM 的 CUDA Core 数量 × 频率，决定了 GPU 的理论算力。

AI 中的 SM

AI 推理时，SM 执行的是 CUDA Kernel： - Elementwise 操作（如 ReLU、SiLU）→ CUDA Core 执行 - 矩阵乘操作（如 GEMM）→ Tensor Core 执行 - Shared Memory 操作（Tiling 加载）→ 软件显式管理

关键洞察：图形渲染中，SM 主要运行 Pixel Shader（大量独立像素计算）；AI 推理中，SM 主要运行 CUDA Kernel（大量矩阵乘 + 元素级计算）。硬件是同一套，但计算模式不同。

TMU（纹理映射单元）—— 图形特有的硬件

图形中的 TMU

TMU 是图形渲染特化的硬件单元，负责： - 纹理采样（tex2D、Sample） - 硬件插值（双线性/三线性/各向异性滤波） - Mipmap 自动选择（LOD 计算） - 纹理压缩解压（BCn 格式）

TMU 的核心优势：硬件自动管理纹理 Cache。你写 tex2D 时，TMU 会自动把纹理数据从 Global Memory 加载到 L1/L2 Cache，你不需要操心。

AI 中没有 TMU

AI 计算没有 TMU 的直接对应物。原因在于 AI 的数据访问模式与纹理采样完全不同：

维度 图形纹理采样（TMU） AI 数据加载
访问模式 空间局部性强：相邻像素采相邻纹素 随机/跨步访问：Attention 的 Q × K^T 是跳跃式访问
硬件加速 TMU + 纹理 Cache 自动搞定 没有专用硬件，需手动用 Shared Memory
数据格式 压缩纹理（BCn），硬件解压 裸张量（FP16/INT8），手动加载
可预测性 可预测：硬件能预取相邻数据 不可预测：硬件 Cache 无法预取跨步数据

你的渲染视角：AI 中你手动写 __shared__ + 指针偏移来加载数据，相当于你用软件自己写了一个 TMU。你不是在"采样纹理"，而是在"手动管理数据搬运"。

ROP（光栅化输出单元）—— 像素的终点

图形中的 ROP

ROP 负责： - 颜色混合（Blending）：BlendState 中的 Alpha 混合 - 深度测试（Depth Test）：Z-buffer 比较 - 模板测试（Stencil Test）：Stencil Buffer 操作 - MSAA 解析（Multisample Resolve）

ROP 是固定功能硬件，不可编程。它的工作是将 Pixel Shader 的输出结果写入 Frame Buffer。

AI 中的 ROP 对应

AI 中没有直接的 ROP 对应物，但在某些场景中可以类比：

ROP 功能 AI 中的对应 说明
Alpha 混合 (Blend) 原子加 (atomicAdd) 多个线程同时写入同一位置时的累加操作
深度测试 (Depth Test) 动态 Padding / Masking 变长序列中屏蔽无效 Token 的计算
写入 Frame Buffer 写回 Global Memory Kernel 计算完成后将结果从寄存器/Shared Memory 写回显存

硬件的统一：图形与 AI 在同一个 GPU 上

现代 GPU（如 NVIDIA A100/H100、AMD MI 系列）是统一架构——同一个 SM 既可以跑 Pixel Shader，也可以跑 CUDA Kernel。

方面 图形渲染模式 AI 计算模式
主要硬件单元 SM + TMU + ROP SM（CUDA Core + Tensor Core）
计算密集单元 SM 的 CUDA Core Tensor Core
访存密集单元 TMU（纹理采样） SM 的 Load/Store 单元
瓶颈通常在哪 TMU（纹理带宽） / ROP（像素填充率） HBM 带宽（数据搬运跟不上计算）
利用率指标 填满率 (Fill Rate)、Draw Call 数 SM Occupancy、算力利用率

关键洞察（你的核心武器）

搞渲染的你，早已理解"哪个硬件单元最慢，就优化哪个"的原则：

  • 图形：TMU 采样慢 → 合并 Pass 减少采样次数，或者用 Mipmap 降低分辨率
  • AI：HBM 带宽不够 → 算子融合减少中间结果读写，或者用 INT8 量化减半数据量

优化思路完全一样，只是被优化的硬件单元不同。

映射速查表

图形硬件单元 AI 计算对应 本质
SM / CUDA Core CUDA Core（标量 ALU） 通用计算单元，执行 Elementwise、Reduce 等
SM / Tensor Core Tensor Core 专用矩阵乘加单元（WMMA API）
TMU（纹理采样） 无直接对应，用 __shared__ + 指针加载替代 图形靠硬件自动 Cache，AI 靠软件显式管理
ROP（Blend） atomicAdd 原子操作 多线程写入同一地址的合并操作
Cache（L1/L2） Cache（L1/L2） 硬件自动管理，图形中命中率高，AI 中命中率低
Shared Memory Shared Memory (__shared__) 软件显式管理，图形不常用（性价比低），AI 必须用（带宽瓶颈）
