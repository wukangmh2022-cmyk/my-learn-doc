3.3 卷积 (Conv2d) 数学与实现 — 多通道 vs 图形模糊，im2col + GEMM 与 Tensor Core¶

概述¶

图形图像卷积（高斯模糊、边缘检测）和 AI Conv2d 在数学公式上完全一致，但在实现上面临截然不同的约束条件。理解这个差异，是打通图形渲染和 AI 推理认知的关键。

核心结论： - 图形卷积是"带宽优化"问题——少采样纹理是王道，哪怕多走一个 Pass - AI 卷积是"算力 + 带宽双重优化"问题——避免重复计算 + 手动分块 (Tiling)

一、标准卷积公式¶

单通道卷积（图形视角）¶

这是你熟悉的图形图像卷积（比如 3x3 高斯模糊）：

Output(x, y) = Σᵢ Σⱼ Input(x+i, y+j) × Kernel(i, j)
  • 图形：Kernel 是固定的（高斯核、Sobel 核），Input 是纹理图片
  • AI：Kernel 是通过训练学出来的随机权重值，Input 是上一层的特征图

多通道卷积（AI Conv2d 完整公式）¶

AI 的卷积是多通道融合的，远复杂于单通道：

Output[c_out, y, x] = Σ_{c_in=0}^{C_in-1} Σ_{i=0}^{K_h-1} Σ_{j=0}^{K_w-1}
    Input[c_in, y+i, x+j] × Weight[c_out, c_in, i, j]

参数含义：

参数 含义 典型值
C_in 输入通道数 RGB=3, 或上一层 64/128/256
C_out 输出通道数（卷积核个数） 64/128/256...
K_h, K_w 卷积核高宽 通常 3×3, 1×1, 5×5
H_in, W_in 输入特征图高宽 取决于网络层

逐层理解¶

Step 1：单个位置的点积

对于输出位置 (y, x) 和单个输出通道：

# 伪代码：3x3 卷积核单点计算
output[y][x] = 0
for i in range(K_h):           # 卷积核行
    for j in range(K_w):       # 卷积核列
        for c in range(C_in):  # 所有输入通道
            output[y][x] += input[y+i][x+j][c] * weight[i][j][c]

Step 2：多输出通道

有 C_out 组不同的权重，每组生成一个输出通道：

for c_out in range(C_out):
    output[c_out][y][x] = sum_over_all(input * weight[c_out])

Step 3：整个特征图

把上面的操作滑动遍历整个 [H_in, W_in] 平面，就是完整的 Conv2d。

计算量对比¶

维度 图形模糊（3×3 高斯） AI 卷积（Conv2d）
输入 单通道灰度图 多通道特征图（如 64 通道）
权重 固定值（如 1/16, 2/16...） 训练出来的随机值
一次卷积循环 for i in 3: for j in 3: sum += ... 外层还要套 for c in range(64) 和 for c_out in range(128)
每个像素计算量 9 次乘加 9 × 64 × 128 ≈ 7 万次乘加

这就是 AI 算力需求爆炸的根本原因：图形做一次 3×3 卷积，每个像素算 9 次乘加；AI 做一次 3×3 卷积，每个像素算约 7 万次乘加（假设 C_in=64, C_out=128）。

二、图形 vs AI：为什么实现方式完全不同？¶

图形：多 Pass 分步卷积¶

以高斯模糊为例：

Pass 1 (水平模糊):  Input → [1×5 卷积核] → Temp Buffer
Pass 2 (垂直模糊):  Temp Buffer → [5×1 卷积核] → Output

为什么这么做？

  • 可分离卷积核：高斯核 G(x,y) = G(x) × G(y)，一个 5×5 可拆成 1×5 + 5×1
  • 带宽优化：纹理采样从 25 次降到 10 次（每像素）
  • 算访比权衡：宁愿多一个 Pass（Render Target 切换），也要少读纹理

AI：单 Pass + Tiling¶

AI 的 Conv2d 是一个 Kernel 直接完成所有通道的卷积：

// 伪代码：AI Conv2d Kernel (单 Pass)
__global__ void conv2d_kernel(float* input, float* weight, float* output,
                               int C_in, int C_out, int H, int W, int K) {
    // 1. 分块加载 (Tiling): 把当前 Tile 的输入和权重搬进 Shared Memory
    __shared__ float tile_input[TILE_SIZE + K-1][TILE_SIZE + K-1][...];
    __shared__ float tile_weight[...];

    load_tile_to_shared(input + ...);
    load_weight_to_shared(weight);
    __syncthreads();

    // 2. 在 Shared Memory 内完成所有通道的乘累加
    float acc = 0;
    for (int ci = 0; ci < C_in; ci++)
        for (int i = 0; i < K; i++)
            for (int j = 0; j < K; j++)
                acc += tile_input[ty+i][tx+j][ci] * tile_weight[co][ci][i][j];

    // 3. 写回 Global Memory
    output[co * H_out * W_out + y * W_out + x] = acc;
}

为什么不拆成两个 Pass？

角度 图形 AI
直接原因 卷积核可分离（高斯核） 卷积核不可分离（随机训练权重）
计算量变化 拆后计算不变（反而省 15 次采样） 拆后计算量暴增约 50%
带宽变化 少采样（省带宽） 多一次中间结果读写（翻倍带宽）
根本原因 瓶颈在纹理采样带宽 瓶颈在计算（Tensor Core）+ 带宽双受限
权衡 多算一点，少读显存 多读显存（一次性全加载），避免重复计算

结论：直接原因 vs 根本原因¶

  • 直接原因：AI 的卷积核不可分离，拆分会导致计算量暴增
  • 根本原因：AI 推理的计算量太大，算力（Tensor Core）成了短板；同时显存带宽也吃紧，所以既不能多算（因为算力不够），也不能多读写（因为带宽不够）

图形：我宁可多算一点（拆成两个 Pass），也要少读显存（纹理采样） AI：我宁可多读显存（一次性把所有输入读进来），也要少算（避免重复计算）

三、权重局部性 vs 输入局部性¶

为什么高性能 Conv 还要显式 Tiling？¶

Conv2d 的局部性特征和图形纹理采样的局部性完全不同：

维度 图形（纹理采样） AI（Conv2d 权重）
局部性类型 采样局部性：相邻像素采相邻纹素 计算局部性：同一权重被不同位置反复使用
瓶颈 TMU 延迟 显存带宽 + 乘加次数
硬件加速 纹理采样路径与 Cache；Compute 也可用 groupshared L1/L2、Shared Memory、寄存器和 Tensor Core 协作
常见方案 Cache、可分离滤波或线程组 Tile direct/implicit GEMM、Winograd 等；是否显式 Shared 取决于实现

Shared Memory 的作用¶

没有 Shared Memory 的情况：

对于 1024×1024 输入，每个输出位置都要从 Global Memory 读取 3×3 权重。这需要约 100 万次权重读取——带宽爆炸。

用了 Shared Memory：

在线程块内加载当前权重与输入 Tile，使该 Block 的多个输出复用它们。复用范围只在该 Block 内，其他 Block 仍需加载；实际流量下降由 Tile 尺寸、通道数和 Cache 行为决定，不会简单降低一百万倍。

权重数值是否随机与地址局部性无关。布局、遍历顺序、Tile 形状和并发工作集共同决定 Cache 与显式 Scratchpad 的收益。

四、im2col + GEMM：AI 卷积的实际实现¶

现代 AI 框架（PyTorch、TensorRT）不会像上面那样写多层嵌套循环，而是用 im2col + GEMM 将卷积转换成矩阵乘法，从而利用 Tensor Core 加速。

im2col 操作¶

im2col（Image to Column）将输入特征图的每个滑动窗口拉直成一列：

输入形状: [C_in, H_in, W_in]

im2col 之后:
一个窗口 (K_h × K_w × C_in 个元素) → 一列

结果矩阵形状: [K_h × K_w × C_in, H_out × W_out]

可视化理解：

输入特征图 (C_in=3, H=4, W=4)       im2col 输出矩阵 (K_h×K_w×C_in, H_out×W_out)
┌──────────────┐                    ┌──────────────────────────────────┐
│  [通道1]     │                    │ 窗口1(拉直) │ 窗口2(拉直) │ ...  │
│  a11 a12 ... │                    │  a11 a12 ... │  a12 a13 ... │     │
│  [通道2]     │                    │  a11 a12 ... │  a12 a13 ... │     │
│  b11 b12 ... │   ─── im2col ──→   │  b11 b12 ... │  b12 b13 ... │     │
│  [通道3]     │                    │  ...         │  ...         │     │
│  c11 c12 ... │                    └──────────────────────────────────┘
└──────────────┘

每一列对应输入特征图上一个滑动窗口的所有值（所有通道 × 所有空间位置）。

GEMM 操作¶

将权重视为矩阵，im2col 结果作为另一个矩阵，直接做矩阵乘：

Weight [C_out, K_h × K_w × C_in] × im2col_Matrix [K_h × K_w × C_in, H_out × W_out]
    → Output [C_out, H_out × W_out]

完整的 two-step 流程¶

# Step 1: im2col
im2col_matrix = im2col(input, kernel_size=3, stride=1, padding=1)
# 形状: [C_in * 3 * 3, H_out * W_out]

# Step 2: GEMM (使用 Tensor Core 加速)
output = weight.reshape(C_out, -1) @ im2col_matrix
# 形状: [C_out, H_out * W_out]

# Step 3: 重排回特征图
output = output.reshape(C_out, H_out, W_out)

为什么把卷积映射为 GEMM？¶

方案 优点 缺点
直接卷积 无需物化展开矩阵，也可使用专用 Tiling/指令 实现复杂，性能依赖形状与硬件
显式 im2col + GEMM 可复用成熟 GEMM 展开矩阵占用额外显存与带宽
Implicit GEMM 按需生成矩阵坐标，不物化完整 im2col 地址计算与边界处理更复杂
Winograd 进一步减少乘加次数 仅适用于特定核大小（3×3），预处理复杂

核心洞察：GEMM 视角把滑动窗口的归约映射到成熟的矩阵乘数据流。生产库常用 implicit GEMM、direct、Winograd 等算法按形状选择，不一定物化 im2col。

Tensor Core 加速¶

Tensor Core 是 NVIDIA 从 Volta 架构开始引入的专用矩阵乘单元。它在一个时钟周期内完成 D = A × B + C 的操作：

// 使用 CUDA wmma API 调用 Tensor Core
#include <mma.h>
using namespace nvcuda;

wmma::fragment<wmma::matrix_a, 16, 16, 16, half, wmma::row_major> a_frag;
wmma::fragment<wmma::matrix_b, 16, 16, 16, half, wmma::col_major> b_frag;
wmma::fragment<wmma::accumulator, 16, 16, 16, float> c_frag;

// 加载 16×16 分块到寄存器
wmma::load_matrix_sync(a_frag, A, 16);
wmma::load_matrix_sync(b_frag, B, 16);
wmma::load_matrix_sync(c_frag, C, 16, wmma::mem_row_major);

// 一次 Tensor Core 矩阵乘
wmma::mma_sync(c_frag, a_frag, b_frag, c_frag);

// 写回
wmma::store_matrix_sync(C, c_frag, 16, wmma::mem_row_major);

Tensor Core 的核心限制：

  1. 提供特定形状与类型的矩阵乘加指令；卷积可通过 implicit GEMM 等映射使用，不要求显式 im2col
  2. 需要特定数据类型（FP16, BF16, INT8 等）
  3. 指令 Tile、布局、对齐和步幅约束随架构、数据类型与 API 变化，不应统一写成 16 的倍数

五、总结对比表¶

维度 图形卷积（高斯模糊） AI 卷积（Conv2d）
卷积核 可分离（固定值） 不可分离（训练随机值）
实现方式 可分离核常用水平 + 垂直 Pass；也可线程组 Tiling direct、implicit GEMM、Winograd 等按形状选择
瓶颈 纹理采样带宽 计算（Tensor Core）+ 显存带宽
缓存方式 纹理 Cache + 可选 groupshared L1/L2 + Shared Memory + Register Tiling
核心加速器 纹理单元 Tensor Core
数据复用 输入数据复用 权重复用（一个权重被滑窗反复使用）
计算密度 低（每像素几十次乘加） 极高（每像素数万次乘加）
底层实现 Shader / 固定采样路径 算法库按形状选择
显存膨胀 多 Pass 有中间表面 仅显式 im2col 会产生较大的展开矩阵

速记公式¶

只需记住这一行，就能推导出所有 Conv2d 相关计算：

输出位置 (y, x, c_out) 的值 = 所有输入通道 c_in 在窗口 (y, x) 内的值，与权重 Weight[c_out, c_in, :, :] 做点积后累加

而 im2col + GEMM 的核心思想是：

把卷积的滑窗访问变成矩阵乘的连续访问，让 Tensor Core 来加速

这就是从图形模糊到 AI 卷积的完整认知升级。
