4.1 算子融合 (Conv+BN+ReLU, FlashAttention 的思想)¶

概述¶

算子融合是 AI 推理优化中最经典、最立竿见影的技术。它的核心思想很简单：

把多个连续的小 Kernel 合并成一个大的 Kernel，减少中间结果在显存（HBM）中的读写次数。

对于搞渲染的你来说，这跟你合并两个 Draw Call 成一个 Pass 的逻辑完全一致。

为什么需要算子融合？¶

融合前的问题¶

假设推理时需要依次执行 Conv → BN → ReLU：

Conv(input) → output_mid
                ↓ (写回显存)
BN(output_mid) → output_mid2
                ↓ (写回显存)
ReLU(output_mid2) → output_final

问题：中间结果 output_mid 和 output_mid2 都需要完整地写回 HBM，再读出来。每次读写 HBM 都是几百个 cycle 的延迟。

融合后的效果¶

FusedKernel(input) → output_final

收益：中间结果留在寄存器 / Shared Memory 中，不写回 HBM。显存访问量减半，推理速度提升 10%~20%，且精度完全无损。

Conv+BN 融合的数学原理¶

这是推理优化里最经典、最立竿见影的操作。

Conv 的计算¶

Y = W * X + B
  • W：卷积权重
  • X：输入特征图
  • B：偏置

BN 的计算（推理时）¶

推理时，BN 的行为变成了固定线性变换：

Y_norm = (Y - mean) / sqrt(var + eps) * gamma + beta

因为推理时 mean、var、gamma、beta 都是训练好之后固定不变的值。

融合推导¶

把 BN 公式展开，代入 Conv 公式：

融合后的权重 W' = W * gamma / sqrt(var + eps)
融合后的偏置 B' = (B - mean) * gamma / sqrt(var + eps) + beta

融合后，推理时直接只跑 Conv（用 W' 和 B'），把 BN 层彻底丢弃。

PyTorch 实现¶

import torch

def fuse_conv_bn(conv, bn):
    # 1. 提取 BN 系数
    gamma = bn.weight
    beta = bn.bias
    mean = bn.running_mean
    var = bn.running_var
    eps = bn.eps

    # 2. 计算缩放因子
    std = torch.sqrt(var + eps)
    scale = gamma / std

    # 3. 融合进 Conv 的 weight 和 bias
    fused_weight = conv.weight * scale.view(-1, 1, 1, 1)

    if conv.bias is not None:
        fused_bias = beta + (conv.bias - mean) * scale
    else:
        fused_bias = beta - mean * scale

    return fused_weight, fused_bias

图形渲染的完美类比¶

Conv+BN 融合 = 合并两个 Draw Call¶

渲染操作 AI 算子融合
两个连续的 Draw Call 两个连续的 Kernel（Conv + BN）
中间结果写入 RT 中间结果写入 HBM
合并成一个 Pass 融合成一个 Kernel
省掉 RT 切换开销 省掉中间结果 HBM 读写

你的直觉完全正确：Conv+BN 融合就是把 Scale 和 Bias 直接算进采样系数里，一次 Pass 搞定——这跟你把矩阵乘法和颜色校正合并到一个 Pass 里，避免多 RenderTarget 写回，逻辑完全一致。

但注意本质差异¶

维度 图形 Pass 合并 AI 算子融合
主要目的 减少 Pipeline Stall（状态切换） 减少显存带宽压力（中间结果读写）
瓶颈类型 同步等待 带宽占用
合并后的收益 GPU 利用率提升 显存访问量减半

更多算子融合的模式¶

1. Conv+BN+ReLU 三段融合¶

最常见的融合模式，将三个 Kernel 合并成一个：

// 伪代码：融合后的 Kernel
__global__ void fused_conv_bn_relu_kernel(/*...*/) {
    // 1. 加载输入 Tile 到 Shared Memory
    // 2. 做卷积（乘加）
    // 3. 应用 BN 系数（scale + bias）
    // 4. 应用 ReLU（max(0, x)）
    // 5. 写回结果到 Global Memory
    // 注意：中间结果不出 Shared Memory！
}

2. Attention 中的 QKV 投影融合¶

Transformer 中的 Q、K、V 三个投影矩阵乘可以合并成一个：

# 融合前
Q = x @ W_q    # 单独矩阵乘
K = x @ W_k    # 单独矩阵乘
V = x @ W_v    # 单独矩阵乘

# 融合后
# 将 W_q, W_k, W_v 拼接成一个大矩阵
W_qkv = torch.cat([W_q, W_k, W_v], dim=1)
QKV = x @ W_qkv      # 一次矩阵乘
Q, K, V = split(QKV)  # 切分结果

3. FlashAttention（融合 Attention 的全部步骤）¶

FlashAttention 本质上就是一个极致的大融合 Kernel：

  • 分块计算 Q×K^T
  • Online Softmax 归一化
  • 乘以 V 并累加

全部在 Shared Memory 内完成，中间矩阵 S 不写回 HBM。详见 6.4 FlashAttention。

你何时需要算子融合？¶

场景 是否值得融合 原因
Conv + BN + ReLU ✅ 绝对值得 经典组合，精度无损，速度提升明显
Conv + Conv（连续两层卷积） ⚠️ 看情况 收益取决于计算密度和中间结果大小
Elementwise + Elementwise ✅ 无脑合 极轻量，融合后 Kernel Launch 开销省掉
Attention 全步骤 ✅ FlashAttention 显存读写减半，速度提升 2~4 倍
不同尺寸的 Kernel ❌ 不要合 合并后线程利用率会下降

你的认知固化¶

算子融合是在 GPU 内部，用更少的显存搬运来换取速度。
CUDA Graph 是在 CPU 和 GPU 之间，用更少的提交次数来换取速度。

这两个优化是正交且互补的：

  1. 先用算子融合：把能合并的 Kernel 都捏成一个，减少显存访问次数
  2. 再用 CUDA Graph：把融合后剩下的大段固定流程录成 Graph，减少 CPU 和 GPU 的交互次数

在真正的 AI 推理引擎中（如 TensorRT、vLLM），这两个优化通常是同时应用的。
