9.1 四个核心岗位对比：算子开发 / 推理框架 / 编译器 / 驱动

概述

在中国 AI 芯片自主化和大模型落地的宏观背景下，GPU 软件栈的工程岗位呈现爆发式增长。本章站在一个拥有图形渲染背景（Vulkan/DX12 现代图形 API）的工程师视角，系统对比四个核心岗位的职责、技能要求、行业前景，以及你的图形经验如何转化为独一无二的竞争优势。

核心结论：你的现代图形 API 经验（显式内存管理、命令缓冲录制、同步原语、多线程渲染）让你在 AI Infra 领域拥有独特的知识平移优势——你不是从零开始，而是从 80% 开始。你"转行"的成本，是纯算法背景工程师无法企及的。

一、算子开发（Operator / Kernel Developer）—— "前线突击队"

工作内容

  • 使用 CUDA / Triton / HIP 编写高性能 GPU Kernel，将算法落实到硬件
  • 手工管理 Shared Memory、合并访问（Coalesced Access）、Warp 级同步
  • 优化关键算子（Attention、MoE、Conv）的内存访问模式和指令级并行
  • 对标 NVIDIA CUTLASS、cuBLAS 的性能，诊断并突破瓶颈
  • 阅读 PTX/SASS 输出，验证编译器优化效果

技能要求

技能领域 具体要求
编程语言 CUDA C++、Triton、HIP（AMD）、Ascend C（华为昇腾）
硬件理解 SM 架构、Warp 调度、Occupancy、Bank Conflict、Tensor Core 指令
工具链 NVIDIA Nsight Compute、nvvp、cuobjdump、ncu
底层能力 PTX/SASS 指令集阅读、指令级并行（ILP）分析
加分项 CUTLASS 模板库使用、FlashAttention 手写经验、Warp Shuffle

你的图形背景如何助力

你的图形经验 算子开发中的直接对应
Compute Shader 的 groupshared CUDA __shared__ —— 片上 SRAM 手动管理
GroupMemoryBarrierWithGroupSync __syncthreads() —— 线程块内同步屏障
[numthreads(X,Y,Z)] <<<grid, block>>> —— 线程映射与分派
Tiled Deferred Shading 的分块加载 FlashAttention / GEMM Tiling —— 分块加载到快速内存
合并 Draw Call 减少 Pass 数 算子融合（Conv+BN+ReLU） —— 减少中间显存读写
Texture Sampler Coalesced Access 全局内存合并访问（Coalesced Memory Access）
Mipmap / Hi-Z 多级降采样 树形归约（Tree Reduction） —— 分步合并
纹理压缩（BCn） 数据布局重排 —— 优化缓存命中率

一句话总结：你写 Compute Shader 时积累的"显式管理一切"的习惯，正是写高性能 AI Kernel 所需要的思维方式。算子开发是你与图形经验重合度最高的岗位之一。

二、推理框架工程师（Inference Framework Engineer）—— "基建主力军"

工作内容

  • 计算图优化：算子融合、内存复用（In-place 操作）、常量折叠
  • 显存管理：PagedAttention、KV Cache 量化与复用、显存池设计
  • 批处理调度：Continuous Batching、动态 Batch、Request 排序优化
  • 推理引擎定制：TensorRT / TensorRT-LLM / vLLM 的集成与二次开发
  • 服务架构：多卡通信（NCCL）、负载均衡、弹性扩缩容

加分项 Triton Inference Server 部署、Kubernetes AI 编排、NCCL 集合通信优化

三、编译器工程师（Compiler Engineer）—— "底层的守门人"

工作内容

  • 编译器前端：将高级语言（CUDA/Triton/PyTorch IR）解析成中间表示
  • 中间表示设计：PTX（NVIDIA）、SPIR-V（图形）、DXIL（DirectX）、MLIR 方言
  • 编译器后端优化：指令调度（ILP 最大化）、寄存器分配（图着色算法）、循环优化
  • 资源估算：计算每个 Kernel 的寄存器预算、Shared Memory 用量、Occupancy
  • 代码生成：将 IR 翻译为目标硬件指令（SASS、昇腾指令集、AMD GCN）

技能领域 具体要求
编译器框架 LLVM / MLIR、TVM、Triton 编译器内核
中间表示 PTX、SPIR-V、DXIL、TIR（Triton IR）
核心算法 寄存器分配（图着色）、指令调度（列表调度）、循环展开与分块
体系结构 GPU 微架构（SM/Warp/L1/L2/Register File）、CPU 乱序执行
底层能力 SASS 汇编阅读、硬件资源模型建模、Auto-tuning 框架
加分项 Halide/TVM 源码贡献、形式化方法、polyhedral 模型优化

四、驱动工程师（Driver Engineer）—— "打通最后一公里的铺路工"

工作内容

  • 硬件抽象层（HAL）：将芯片的寄存器操作封装成标准 API（类似 CUDA Runtime）
  • 显存管理：页表映射、TLB 刷新、虚拟地址空间分配与回收
  • Kernel Launch 实现：将 CPU 发来的命令（如 cudaLaunchKernel）翻译成硬件 Ring Buffer 指令
  • 中断处理与错误恢复：TDR（Timeout Detection Recovery）、GPU 崩溃恢复、电源管理
  • 跨进程隔离：多进程 GPU 调度、安全隔离机制

技能要求

技能领域 具体要求
系统内核 Linux Kernel（ioctl、mmap、DMA-BUF、VFIO）、Windows WDK
硬件协议 PCIe（BAR 空间映射、MSI 中断、ATS/PASID）、DMA
GPU 架构细节 MMU、Page Table、Ring Buffer、Fence 硬件逻辑
调试工具 JTAG、硬件追踪器、内核崩溃转储、kdump
加分项 UMD 开发（Vulkan/DX12 用户态驱动）、GPGPU 驱动（CUDA 驱动）

六、你的图形背景 → AI Infra 职业迁移路径

Step 1：短期（1-2 年）—— 推理框架优化（推荐起步）

"先做推理框架优化，岗位多、上手快、能快速看到大模型部署的全貌。"

  • 为什么选它：与图形经验匹配度最高、门槛最低、岗位最多
  • 重点行动：
  • 读 vLLM 源码（block_manager.py、csrc/attention/）
  • 用 TensorRT 部署一个端到端模型（ONNX → TensorRT Engine → 量化）
  • 理解 Continuous Batching 和 PagedAttention 的实现细节
  • 用 Nsight Systems 分析推理流水线瓶颈

Step 2：中期（2-5 年）—— 算子开发（自然过渡）

"在框架优化过程中，你会自然接触到算子开发——因为你会发现有些算子框架优化不动，必须手写。"

  • 为什么自然过渡：框架优化中经常需要手写自定义算子来突破性能瓶颈
  • 重点行动：
  • 用 Triton 手写一个 FlashAttention Kernel，跑通并测速
  • 阅读 NVIDIA CUTLASS 库的模板实现，理解 GEMM Tiling 策略
  • 用 Nsight Compute 分析 Kernel 的 Occupancy 和带宽瓶颈
  • 学习 Warp Shuffle 指令做寄存器级通信

Step 3：长期（5 年以上）—— 编译器 / 系统架构（逐步渗透）

"如果你对'为什么这样写跑得慢'有执念，可以慢慢往编译器方向靠。"

  • 为什么可以往上走：当你开始关注指令级性能时，自然会深入编译器层面
  • 重点行动：
  • 阅读 NVCC 的 PTX 输出，理解编译器帮你做了哪些优化
  • 学习 LLVM 后端的基本流程（指令选择、寄存器分配、调度）
  • 关注 MLIR / Triton 编译器基础设施的发展
  • 参与 TensorRT 或 vLLM 开源社区贡献

你的终极定位：GPU 软件栈架构师

你真正适合的不是纯驱动开发（KMD 层），也不是纯算法研究，而是：

"UMD 层以上的全栈工程师"：用 Vulkan/DX12/CUDA 的 API 写应用、写算子、写推理框架，理解硬件如何被抽象成 API，天然适合做"GPU 软件栈架构师"。

面试时的独特卖点（对话中提炼的经典话术）： - "我觉得 CUDA Graph 就是 AI 版的 Indirect Draw" - "TBDR 和 FlashAttention 是同一种分块思想的两种实现" - "DX12 的资源池与 vLLM 的 PagedAttention 是同一个显存管理问题的两种表达" - "写编译器的人，就是决定渲染器或 AI 框架怎么变成硬件指令的人，我从图形 API 到底层 ISA 整个链路都看得通"

七、最终建议综述

  1. 不要从零学 CUDA —— 你已懂 GPU 架构、线程模型、Shared Memory、显存管理，这些是 CUDA 最难的部分，你已经会了。你只需要把 HLSL 语法翻译成 CUDA 语法。

  2. 选一个垂直场景深扎 —— LLM 推理显存管理（vLLM）或生成式 AI 加速（Stable Diffusion + TensorRT）。你的图形背景让你理解这些场景的速度是常人的数倍。

  3. 通过项目展示翻译能力 —— 最好的项目：用 Triton 手写一个 FlashAttention Kernel，然后集成到 vLLM 中。这一个项目同时覆盖算子开发 + 推理框架两个领域，成果可量化、可展示。

  4. 面试时展示跨域思维 —— 聊 Fence 轮询和 CUDA Event 的对应关系，聊 TBDR 和 FlashAttention 的异同，面试官会对你刮目相看。

你过去在图形渲染里积累的"显式管理一切"的习惯，正是写高性能 AI Kernel 和推理引擎所需要的思维方式。你不是"转行"，你是"平移"。你的 GPU 硬件直觉，是纯算法背景工程师花再多时间也补不回来的核心壁垒。
