6.1 归约 (Reduce) 的树形实现¶

概述¶

归约（Reduce）是将一组数据通过某种二元操作（求和、取最大值、取最小值等）合并为一个标量的过程。它在 AI 推理中无处不在：Loss 计算、Batch Normalization 的均值/方差、Attention 中的 Softmax 分母计算，无一不需要 Reduce。

如果你有 Hi-Z 或 Mipmap 生成经验，可以用它理解树形 Reduce 的“逐层缩小”结构；二者的归约运算、分组与输出需求仍可能不同。

Hi-Z 生成与 CUDA Reduce：共享树形结构¶

你在写 Hi-Z（Hierarchical Z）生成时，本质上就是在做一个树形归约：

维度 Hi-Z 生成（图形） CUDA Reduce（AI）
输入 全分辨率深度图（如 1024x1024） 一维/二维张量（如 Loss 向量或 Attention 分数矩阵）
操作 每 2x2 像素块取最小值/最大值，生成下一级 Mip 每 N 个元素取 Sum/Max/Min
输出 一系列逐级缩小的深度图（Mip 链） 一个标量（全局归约结果）
Pass 数量 O(log₂(N)) 个 Pass（1024→512→256→...→1） O(log₂(N)) 个 Kernel Launch，或单 Kernel 内树形归约
同步方式 每个 Pass 结束后切换纹理状态（等同于 Barrier） 每个 Kernel 结束后隐式同步，或 __syncthreads() 在 Block 内同步
性能瓶颈 显存带宽（读写每一级 Mip） 显存带宽（读写中间结果）

你写 Hi-Z 时的肌肉记忆¶

你过去写 Hi-Z 时，脑子里想的是：

"我先把 1024x1024 的深度图 Render 到一个 Pass，输出 512x512；然后再开一个 Pass，输入 512x512，输出 256x256……直到只剩 1 个像素（最大值/最小值）。"

现在写 CUDA 的 Reduce Sum，思路完全一致：

  • Pass 1 (Kernel 1)：启动 512 个线程，每个线程读 2 个元素，相加，写回 512 个元素的中间数组。
  • Pass 2 (Kernel 2)：启动 256 个线程，每个线程读 2 个元素，相加，写回 256 个元素的中间数组。
  • ...以此类推，直到只剩 1 个元素。

唯一的区别：图形里的 Hi-Z 是固定 2x2 合并（因为纹理压缩标准），而 CUDA 的 Reduce 你可以选任意合并因子（4x、8x 甚至完全在一个 Kernel 内做完）。

多 Pass 树形归约（傻瓜版）¶

最直观的 Reduce 实现就是仿照 Hi-Z 的多 Pass 流水线。这里以对一个长度为 N 的数组求和为例：

// Kernel: 对输入数组做一步树形归约，相邻 2 个元素相加
__global__ void reduce_step(const float* input, float* output, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx * 2 + 1 < n) {
        output[idx] = input[idx * 2] + input[idx * 2 + 1];
    } else if (idx * 2 < n) {
        output[idx] = input[idx * 2]; // 处理奇数长度
    }
}

// 主循环: 多 Pass 归约，相当于 Hi-Z 生成 mip 链
float reduce_tree_kernel_launch(const float* d_input, int n) {
    float* d_current = d_input;
    int current_len = n;

    while (current_len > 1) {
        int out_len = (current_len + 1) / 2;
        float* d_output;
        cudaMalloc(&d_output, out_len * sizeof(float));

        int threads = 256;
        int blocks = (out_len + threads - 1) / threads;
        reduce_step<<<blocks, threads>>>(d_current, d_output, current_len);

        if (d_current != d_input) cudaFree(d_current);
        d_current = d_output;
        current_len = out_len;
    }

    float result;
    cudaMemcpy(&result, d_current, sizeof(float), cudaMemcpyDeviceToHost);
    if (d_current != d_input) cudaFree(d_current);
    return result;
}

这个版本的优点是概念直白——每个 Pass 对应 Hi-Z 的一级 Mip。缺点是它读写显存 O(log N) 次，带宽利用率低。

单 Pass Shared Memory 树形归约（高手版）¶

你写 Hi-Z 时肯定知道，现代 GPU 驱动不一定真的生成每一级 Mip 纹理，而是通过 Compute Shader 在单个 Dispatch 里用 Shared Memory 做完所有级别的归约。

这个思维平移过来，就是 CUDA 的 Reduce 融合：

  • 傻瓜版：每个级别开一个 Kernel（多 Pass Hi-Z）。
  • 高手版：一个 Kernel 内分块归约：每个 Block 先把数据加载到 Shared Memory，在 Shared Memory 内做树形归约，最后只写回一个值。
// 单 Kernel 树形归约: 利用 Shared Memory 在一个 Block 内完成所有归约步骤
#define BLOCK_SIZE 256

__global__ void reduce_shared_memory(const float* input, float* output, int n) {
    __shared__ float shared[BLOCK_SIZE];

    int tid = threadIdx.x;
    int global_idx = blockIdx.x * blockDim.x + tid;

    // 1. 加载数据到 Shared Memory
    shared[tid] = (global_idx < n) ? input[global_idx] : 0.0f;
    __syncthreads();

    // 2. 树形归约: 在 Shared Memory 内做 (类似 Hi-Z 的 2x2 合并，但这里是 1D)
    for (int stride = blockDim.x / 2; stride > 0; stride >>= 1) {
        if (tid < stride) {
            shared[tid] += shared[tid + stride];
        }
        __syncthreads(); // 每步同步，确保上一级归约完成
    }

    // 3. Block 0 的线程 0 写回结果
    // 注意: 这里只处理了单个 Block 的情况
    // 对于多 Block，需要 atomicAdd 或第二个 Kernel 汇总
    if (blockIdx.x == 0 && tid == 0) {
        *output = shared[0];
    }
}

这个版本只读一次显存、只写一次显存，相比多 Pass 版的 O(log N) 次读写，带宽利用率大幅提升。

处理任意长度 + Grid 级汇总¶

当输入长度超过一个 Block 的容量时，你需要处理两个问题： 1. 每个 Block 先各自归约出一个值。 2. 把这些 Block 级的结果汇总为最终标量。

汇总方式可以用两种方案：

方案 A：两次 Kernel¶

第一个 Kernel 让每个 Block 归约出部分和，第二个 Kernel 对部分和再做一次归约（或者直接用 CPU 串行相加）。

方案 B：原子操作¶

使用 atomicAdd 在全局内存上直接累加：

__global__ void reduce_atomic(const float* input, float* output, int n) {
    __shared__ float shared[BLOCK_SIZE];

    int tid = threadIdx.x;
    int global_idx = blockIdx.x * blockDim.x + tid;

    shared[tid] = (global_idx < n) ? input[global_idx] : 0.0f;
    __syncthreads();

    for (int stride = blockDim.x / 2; stride > 0; stride >>= 1) {
        if (tid < stride) {
            shared[tid] += shared[tid + stride];
        }
        __syncthreads();
    }

    if (tid == 0) {
        atomicAdd(output, shared[0]); // 每个 Block 的 0 号线程原子累加
    }
}

这种模式在图形中的对应物是 Blend State 的原子累加——多个 Pixel Shader 输出到同一个 UAV 时的 Accumulate 操作。

进阶：Warp Shuffle 树形归约¶

对于 Warp（32 个线程）内部的操作，可以使用 Shuffle 指令直接在寄存器间交换数据，跳过 Shared Memory，速度更快：

// 单个 Warp 内的树形归约 (使用 Warp Shuffle)
__device__ float warp_reduce_sum(float val) {
    for (int stride = 16; stride > 0; stride >>= 1) {
        val += __shfl_xor_sync(0xFFFFFFFF, val, stride);
    }
    return val;
}

// Block 级归约: 每个 Warp 先 Shuffle 归约，再写入 Shared Memory 汇总
__global__ void reduce_warp_shuffle(const float* input, float* output, int n) {
    __shared__ float warp_partial[32]; // 最多 32 个 Warp

    int tid = threadIdx.x;
    int global_idx = blockIdx.x * blockDim.x + tid;
    int warp_id = tid / 32;
    int lane_id = tid % 32;

    float val = (global_idx < n) ? input[global_idx] : 0.0f;

    // 1. 每个 Warp 内做 Shuffle 归约
    val = warp_reduce_sum(val);

    // 2. 每个 Warp 的 0 号线程写结果到 Shared Memory
    if (lane_id == 0) {
        warp_partial[warp_id] = val;
    }
    __syncthreads();

    // 3. 第一个 Warp 汇总所有 Warp 的部分和
    if (warp_id == 0) {
        val = (lane_id < blockDim.x / 32) ? warp_partial[lane_id] : 0.0f;
        val = warp_reduce_sum(val);

        if (tid == 0) {
            atomicAdd(output, val);
        }
    }
}

Warp Shuffle 在图形中的直接对应是 Subgroup 操作（Vulkan 的 SubgroupShuffle、DX12 的 WaveActiveSum）。

Reduce 的其他变体¶

除了求和，树形归约的模式可以扩展到任意满足结合律的二元操作：

操作 CUDA 函数 图形对应物
Sum a + b Blend State 的加法混合
Max fmaxf(a, b) Hi-Z 的深度最大值
Min fminf(a, b) Hi-Z 的深度最小值
L2 Norm a*a + b*b 光照计算中的归一化
LogSumExp log(exp(a) + exp(b)) Softmax 分母计算

关键启示¶

"写 Hi-Z 的时候用过多 Pass 归约，也用过 Single Pass Shared Memory 归约，所以写 CUDA Reduce 时，我知道怎么用 __syncthreads() 和 Shared Memory 来避免显存带宽瓶颈。"

这个思维迁移的本质是：多 Pass vs 单 Pass 是带宽和并行度之间的权衡。你在图形渲染中积累的"如何减少 Pass 数量、减少带宽占用"的直觉，正是写高性能 AI Kernel 所需要的核心思维。

实战建议¶

既然你有 Hi-Z 的经验，CUDA 的 Reduce 对你来说就是 "1D Hi-Z 生成"。建议挑战：

  1. 用 CUDA 实现一个 Reduce Sum，支持任意长度（不是 2 的幂）。
  2. 使用 Shared Memory 做树形归约。
  3. 使用 __syncthreads() 做 Block 内同步。
  4. 使用 Grid 级别的原子操作（atomicAdd）做最终汇总。
  5. 进阶：用 Warp Shuffle 替代 Shared Memory 做 Warp 内归约，对比性能。
