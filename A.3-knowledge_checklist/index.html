A.3 关键知识点自检清单¶

概述¶

这份自检清单基于本书 11 章技术主线，采用熟练、理解、待学三级掌握度评估，帮助具有图形渲染背景的工程师定位 AI Infra 知识短板并规划学习路径。

注意：掌握度评估面向图形背景读者。你不需要像纯新手一样\"从零学\"，而是检查自己是否已经完成了\"图形概念→AI 概念\"的翻译和实战验证。你已经会的东西，直接跳过。

掌握度等级定义¶

符号 含义 判断标准
✅ 熟练 能脱离类比解释概念，写出正确实现，并用测试或 Profiler 数据验证 定期复测，不必重复入门材料
🟡 理解 你用直觉能猜对，但没实际写过代码或读过论文，需要一次实战验证 花一天快速验证
❌ 未知 你还不清楚这个概念在讲什么，或者没有对应的图形经验可以平移 需要系统学习

第 4 章：AI 推理优化核心策略¶

这是你的\"优势区\"——你对绝大多数概念有深刻的图形直觉。

分块（Tiling）与局部性 ✅ 熟练 TBDR → FlashAttention 是你自己推导出来的——\"分块加载到 Shared Memory，减少全局访存\" 4.2
异步流水线（通信 behind compute / 双缓冲 / DMA 重叠） 🟡 理解 你\"创造\"了这个词 Communication behind compute，但没亲手调过多卡通信重叠 4.3
显存管理（PagedAttention / 类比 DX12 资源池） ✅ 熟练 你的核心优势：聊 PagedAttention 就像聊 DX12 的伙伴分配器——因为你看到了同一个抽象 4.4

自检问题：你是否能用\"合并 Pass\"的直觉推导 Conv+BN+ReLU 融合算子的设计思路，并指出中间数据如何从显存读写变为片上 SRAM 访问？

Warp / SIMD / SIMT / 分支分歧 ✅ 熟练 你从渲染经验中深刻理解\"32 个线程一起走，分支就是性能杀手\"——ReLU 被编译成 max 指令就是例子 5.3

Week 1 推理部署全流程：YOLOv8/vgg16 导出 ONNX → TensorRT Engine 编译 → INT8 量化 → 测延迟 \"抓帧分析 + 优化 Pass + 纹理压缩\"的 AI 版 TensorRT 官方 Sample（sampleOnnxMNIST）
Week 2 异步流水线实战：用 CUDA Stream 实现 D2D 拷贝 + Kernel 计算的重叠，体验 cudaMemcpyAsync + cudaEventQuery 轮询 DX12 异步 Compute + 三重缓冲 CUDA Programming Guide \"Asynchronous Concurrent Execution\"
Week 3 读推理框架源码：读 vLLM 的 csrc/attention/ 目录，理解 FlashAttention 的 CUDA 实现和 BlockManager 设计 \"读你自己的 DX12 资源池代码，只是换了名字\" vLLM GitHub + FlashAttention Paper

3 周后你能做到：独立完成一个模型从训练权重到推理加速引擎的全链路部署，并理解每个环节的性能瓶颈。

🎯 3 个月专项：成为稀缺交叉人才¶

三选一方向，强烈推荐方向 A（覆盖算子开发 + 推理框架两个领域）：

方向 目标 核心资源 成果形式
A: Triton FlashAttention 用 Triton 从零手写 FlashAttention Kernel，集成到 vLLM 替换默认实现 Triton 官方教程 + FlashAttention 论文 + vLLM Kernel 源码 可量化的延迟提升数据
B: vLLM 显存管理改造 修改 vLLM 的 BlockManager，实现一种新的显存分配策略（如 Slab Allocator 应对异构模型） vLLM 源码 vllm/core/block_manager.py + Jenga 论文 新的显存分配器 Demo
C: AI 编译器入门 用 TVM/Triton 做自动调优编译，写一个简单的算子自动调优 Pass TVM 官方文档 + MLIR 入门 + Triton 编译器内核 自动调优脚本 + 性能对比

3 个月后的合理验收：完成一个可复现项目，包含正确性基线、不同形状的 Benchmark、Profiler 分析、失败案例和文档。职级取决于工程范围、影响力与组织标准，不能由学习时长推导。

附 B：推荐学习资源¶

必读文档¶

资源 用途 你的阅读策略
CUDA C++ Programming Guide CUDA 权威参考 跳过架构介绍（你已懂 GPU），只看 Kernel 定义、内存管理、Stream/Event 章节
CUDA C++ Best Practices Guide 性能优化圣经 只看 \"Performance Optimization\" 章节，重点关注 Occupancy 和 Memory Access 部分
TensorRT 官方 Sample（sampleOnnxMNIST） TensorRT 入门 跑通一个 Sample 即可，其余 API 按需查阅
vLLM 源码（GitHub） 实战源码阅读 重点关注 csrc/attention/（Kernel 实现）、vllm/core/block_manager.py（显存管理）
Triton 官方教程 算子编写入门 重点关注 \"Matrix Multiplication\" 和 \"FlashAttention\" 教程

必读论文¶

论文 你的阅读策略 核心价值
FlashAttention（Dao et al., 2022, NeurIPS） 跳过公式推导，用 TBDR/TDS 的思维去理解数据流向图 用你已有的分块直觉验证 Online Softmax 的核心思想
PagedAttention（Kwon et al., 2023, SOSP） 当成\"虚拟内存分页在显存管理中的应用\"来读，类比你的 DX12 资源池 证明你的显存管理直觉和学术界一致
GPU 统一计算架构（Nickolls et al., 2008） 经典论文，了解 GPU 从图形专用到通用计算的演进动机 理解 GPU 架构设计的\"第一性原理\"
Reduction / Scan 经典算法（Blelloch, 1990） 树形归约和前缀和的经典教材 填补你在通用 GPU 算法上的知识盲区

必用工具（你的上手策略）¶

工具 图形对标 你的上手策略
Nsight Compute = PIX / NSight Graphics 的\"AI 版\" 你已经会同类工具，直接上手分析你的第一个 Kernel 的 Occupancy 和带宽
Nsight Systems = GPU 时间线 Profiler 用于看 CPU-GPU 时间线，检查异步流水线是否有效重叠
TensorRT = \"AI 版 HLSL 编译器 + PSO 缓存\" 你理解它的工作流：定义计算图 → 编译 → 序列化 → 推理
PyTorch（推理视角） = \"操作 GPU 显存上多维数组的库\" 先当 API 调用者，不急着深入源码

附 C：面试前自测 10 题（图形背景版）¶

这 10 个问题来自对话中的讨论，旨在检验你能否将图形直觉清晰地翻译为 AI Infra 领域的表达。

  1. 用一句话说清 \"CUDA Graph\" 和 \"RenderGraph\" 的区别和联系。

  2. 解释为什么 \"三角形数量 ≈ 模型参数量\"、\"像素填充率 ≈ 推理计算量\"——两个领域在性能分析上的类比逻辑。

  3. 描述从 cudaMalloc 到 VkDeviceMemory 的映射关系，并说明两者在显存管理设计哲学上的差异。

  4. 解释 PagedAttention 为什么像操作系统虚拟内存分页？它解决了什么类似的问题（碎片 / 大块连续内存 / 按需分配）？

  5. 如果你要在 GPU 上对一个长度为 1024 的数组做 Reduce Sum，最少需要几个 Kernel Launch？画出树形归约的数据流向图。

  6. 什么是 Warp Divergence？在 Shader 编程中有没有对应的概念（Wavefront / 分支掩蔽）？

  7. __syncthreads() 对应图形 API 中的什么机制？它和 GroupMemoryBarrierWithGroupSync() 有什么区别？

  8. VkDeviceMemory 的手动管理经验如何帮助你理解 vLLM 的 BlockManager 设计？如果把 PagedAttention 改成伙伴分配器，你觉得会有什么优缺点？

  9. 用你自己的语言解释 Continuous Batching 和 帧并行（Frame Parallelism） 的相似性，以及它们各自要解决的核心问题。

  10. 描述从 GPU Driven Pipeline（Indirect Draw / ExecuteIndirect）到 AI 推理的 CUDA Graph 调度 的类比，并指出它们之间是否存在不能完全等价的地方？
