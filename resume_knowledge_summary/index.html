概述

本章的核心目的：帮助你用 AI Infra 的语言，把你的图形渲染功力写进简历。

你已有的 GPU 底层知识（显存管理、并行调度、硬件架构）是 AI 推理优化的核心硬技能，只是命名体系不同。下面的内容按 硬件 → 系统 → 算法 → 应用 四个层级展开，每项都附带： - 你的掌握程度评估 - 图形经验对标说明（让你知道\"这我已经会了\"） - 简历关键词（让你直接抄到简历上）

记住：你不是一个\"从图形转行 AI 的新人\"，你是一个\"既懂 GPU 硬件系统、又懂 AI 推理算法\"的稀缺复合人才。你的简历要传递的是：你拥有纯算法背景工程师不具备的硬件底盘视角。

一、硬件与芯片架构层（你的核心壁垒）

这是你最深厚的内功。纯算法背景的工程师很少能触及这一层，而这正是你做推理优化的最大优势。

知识要点

这一层是你图形 API 经验最直接的平移区域。Vulkan/DX12 的\"显式控制一切\"的设计哲学，与高性能 CUDA 编程完全相同。

三、AI 推理算法与模型层（你的快速学习区）

你对这一层的直觉非常准——你在第一次接触 FlashAttention 时就准确地说出了\"这跟 TBDR 一样\"，第一次看到 PagedAttention 时就认出\"这跟 DX12 资源池一样\"。你缺少的是论文阅读量、公式推导和代码实战打磨，但这只需时间积累。

\"多 RT（Render Target）并行写入\" \"张量并行（Tensor Parallelism）\" 都是多目标/多设备并行处理数据

\"你从硬件底层往上长的视角\" \"我理解 GPU 的方式是从硬件执行模型出发，向上推导 API 设计的原因、框架优化的方向和 Kernel 实现的约束条件——而不是从上往下查文档。\"
\"你把两个系统翻译成同一个抽象\" \"CUDA Graph 对我来说就是 AI 版的 Indirect Draw——都是一次录制、多次提交，都为了减少 CPU-GPU 交互的开销。理解这个抽象后，Kernel Launch 优化就成了直觉。\"
