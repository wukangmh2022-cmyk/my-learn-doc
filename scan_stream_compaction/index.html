6.2 扫描 (Scan / Prefix Sum) 与流压缩 (Stream Compaction)

概述

Scan（扫描，亦称前缀和 Prefix Sum）是 GPU 并行计算中最重要的基础设施算子。它本身不完全产生业务价值，但它是 Stream Compaction、Radix Sort、甚至 FlashAttention Online Softmax 的底层引擎。

如果你熟悉图形渲染，你会发现 Scan + Stream Compaction 就是你用 Compute Shader 做粒子剔除（Particle Culling）的那一套流水线。

Gather、Scatter、Scan：用图形语言翻译

这三个算子对应的是不规则内存访问模式，在图形里你天天都在用：

算子 数学本质 图形等价 AI 应用场景
Gather 根据索引读数据 tex2D(tex, uv) 纹理采样、顶点 Buffer Index Fetch Embedding 查表、Attention 从 V 取值
Scatter 根据索引写数据 写入 UAV (RWStructuredBuffer[idx] = val)、Stream Out MoE 梯度回传、Sparse Attention 输出
Scan 前缀累积计算 流压缩 (Stream Compaction)、Mipmap 的 Summed Area Table FlashAttention Online Softmax、动态偏移计算

图形中的经典流水线：粒子剔除

这是把 Gather → Scan → Scatter 串起来的最直观场景：

1. Gather:   每个线程从 Buffer 读取一个粒子的位置
2. 计算:     判断粒子是否在视锥内 (生成 0/1 Flag)
3. Scan:     对 Flag 数组做前缀和，计算每个存活粒子的新索引
4. Scatter:  根据新索引，把存活粒子写入 Compact Buffer

AI 的完全对应场景是 MoE 路由：

1. Gather:   根据路由分数 (Score)，从专家权重表中取出对应的行
2. 计算:     当前 Token 在专家里的前向传播
3. Scan:     如果要做动态 Padding，用前缀和计算每个 Token 在输出中的偏移
4. Scatter:  将计算结果散射回输出序列的对应位置

流水线结构完全一样，只是输入从\"粒子位置\"变成了\"Token 向量\"。

前缀和 (Prefix Sum / Scan)

定义

对于输入数组 A = [a0, a1, a2, ..., an-1]，包含式前缀和输出：

B[0] = A[0]
B[1] = A[0] + A[1]
B[2] = A[0] + A[1] + A[2]
...
B[n-1] = A[0] + A[1] + ... + A[n-1]

排除式前缀和输出（第一个元素为 0）：

B[0] = 0
B[1] = A[0]
B[2] = A[0] + A[1]
...
B[n-1] = A[0] + A[1] + ... + A[n-2]

这两种变体在流压缩中各有用处，通常在 Scatter 阶段使用排除式来获得目标写入位置。

并行 Scan 算法：两种经典实现

1. Hillis-Steele (朴素并行 Scan)

// Hillis-Steele 算法: 多轮迭代，每轮步长加倍
__device__ void scan_hillis_steele(float* shared, int tid, int n) {
    for (int stride = 1; stride < n; stride *= 2) {
        float temp = shared[tid];
        if (tid >= stride) {
            temp += shared[tid - stride];
        }
        __syncthreads();
        shared[tid] = temp;
        __syncthreads();
    }
}
  • 时间复杂度：O(n log n)（总工作量，不是最优的）
  • 并行深度：O(log n)
  • 特点：直观但多做了 log n 倍的工作

2. Blelloch (工作高效 Scan)

// Blelloch 算法: 上行扫 (Reduce) + 下行扫 (Downsweep)
__device__ void scan_blelloch(float* shared, int tid, int n) {
    // 第一阶段: 上行扫 (Up-sweep / Reduce)
    for (int stride = 1; stride < n; stride *= 2) {
        int idx = (tid + 1) * stride * 2 - 1;
        if (idx < n) {
            shared[idx] += shared[idx - stride];
        }
        __syncthreads();
    }

    // 置零根节点
    if (tid == n - 1) {
        shared[tid] = 0;
    }
    __syncthreads();

    // 第二阶段: 下行扫 (Down-sweep)
    for (int stride = n / 2; stride > 0; stride /= 2) {
        int idx = (tid + 1) * stride * 2 - 1;
        if (idx < n) {
            float temp = shared[idx];
            shared[idx] += shared[idx - stride];
            shared[idx - stride] = temp;
        }
        __syncthreads();
    }
}
  • 时间复杂度：O(n)（最优，总工作量跟串行一样）
  • 并行深度：O(log n)
  • 特点：工作高效，但实现更复杂

这两种算法都在 CUDA CUB 库中有高度优化的实现 (cub::BlockScan)，它会自动根据你的 GPU 架构选择最优策略并做循环展开。

流压缩 (Stream Compaction)

流压缩是 Scan 最直接的应用：从数组中筛选出满足条件的元素，并紧凑地写到新数组。

三步法

输入数组:    [A, B, C, D, E]   (5 个元素)
Flag 数组:   [1, 0, 1, 0, 1]   (1=保留, 0=丢弃)

Step 1. Map (标记)     → 生成 Flag 数组
Step 2. Scan (前缀和)  → 对 Flag 做排除式前缀和: [0, 1, 1, 2, 2]
Step 3. Scatter (散射) → 根据前缀和结果写入新位置:
                            A → Compacted[0]
                            C → Compacted[1]
                            E → Compacted[2]
                         Compacted: [A, C, E]  (3 个元素，已紧凑)

流压缩的时间复杂度

步骤 复杂度 说明
Map (标记) O(n) 遍历一次数组，生成 0/1 标记
Scan (前缀和) O(n) 但对 GPU 并行执行延迟只有 O(log n)
Scatter (散射) O(n) 再遍历一次，根据前缀和结果写入新位置
总工作量 O(n) 三次遍历
并行延迟 O(log n) 真正的执行时间

CUDA 实现示例

// 流压缩 Kernel: 筛选出所有大于阈值的元素
__global__ void stream_compaction(const float* input, const int* flags, 
                                   float* output, int* compacted_count, 
                                   int n) {
    __shared__ float shared_scan[256];

    int tid = threadIdx.x;
    int global_idx = blockIdx.x * blockDim.x + tid;

    // 1. 加载 Flag 到 Shared Memory（做 Scan）
    shared_scan[tid] = (global_idx < n) ? flags[global_idx] : 0;
    __syncthreads();

    // 2. 并行 Scan: 用 Blelloch 算法
    scan_blelloch(shared_scan, tid, blockDim.x);

    // shared_scan 现在包含排除式前缀和

    // 3. Scatter: 根据前缀和结果写入输出
    if (global_idx < n && flags[global_idx]) {
        int write_pos = shared_scan[tid];
        output[write_pos] = input[global_idx];
    }

    // 4. 最后一个线程写入紧凑后的总元素数
    if (tid == blockDim.x - 1) {
        // 注意: 这里的处理简化了多 Block 的汇总
        // 实际需要多个 Block 时需额外合并步骤
        if (blockIdx.x == 0) {
            *compacted_count = shared_scan[blockDim.x - 1] + flags[blockDim.x - 1];
        }
    }
}

注意：上述代码为了展示流压缩的三步模式，做了简化。生产环境推荐直接使用 CUB 库的 cub::DeviceSelect，它已经融合了所有优化（Warp Shuffle、循环展开、多 Block 汇总）。

图形中的流压缩变体：Summed Area Table

你在图形渲染中可能已经用过另一种形式的 Scan——SAT (Summed Area Table)：

  • 对一张二维纹理做水平方向的前缀和，再做垂直方向的前缀和。
  • 得到 SAT 后，任意矩形的元素和只需 4 次纹理采样（O(1) 查询）。
  • 这就是二维 Scan 在渲染中的经典应用，常用于 Variance Shadow Map、HDR Bloom 等。

总结

概念 你早已掌握的图形经验 在 AI 中的新应用
Scan (前缀和) Mipmap 的 Summed Area Table FlashAttention Online Softmax、动态偏移
Stream Compaction Compute Shader 粒子剔除 MoE 稀疏路由、Sparse Attention
Gather 纹理采样 (tex2D) Embedding 查表、Attention 的 V 查找
Scatter UAV / Stream Out 写入 梯度散射、Token 位置重排

Scan 的核心理念：把一串不连续的 Flag 转换为一组连续的位置偏移——这就是 GPU 上所有\"稀疏变密集\"操作的基础。你写的每一行粒子剔除代码，本质都是在做这件事。现在只是在不同的数据上重复同一个模式。
